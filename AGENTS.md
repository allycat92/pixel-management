# Notes for coding agents (Codex, Claude, ...)

- Game: vanilla HTML/CSS/JS. Open `index.html` via any static server (`python3 -m http.server`).
- Art workflow: see `art/README.md` (image agents draw and push PNGs to the `art-inbox` branch;
  `tools/art/process.py` converts portraits/events/backgrounds into `assets/art/`).
- Battle character sheets: `python3 tools/art/sheets.py` turns `art/inbox/sheet_*.png` (1x4 key-pose strip,
  2x2 grid, or one full-body pose on flat #FF00FF) into an 80x80-cell sheet (body ~64px, feet at 40,76,
  breathing idle via sprite-gen; one file at a time, never the `*_mounted` preview; every sheet request carries `scale`, `cell`,
  `layout`, key colours `tint` and must-keep `spots` in `phase3.json` (from `node tools/art/requests.js`), which `sheets.py` applies
  itself — no flags) and registers it with `tools/art/register_sheet.py` as `sheet/<kind>/<key>`
  in `assets/art/manifest.json`. Requests: `art/requests/phase3.md` (generated by `node tools/art/requests.js`).
  `process.py` never drops manifest entries it did not produce.
- Run/walk frames: `python3 tools/art/add_gait.py <sheet> --gait run|walk --src <a.png> <b.png>|<x.aseprite> --pose art/requests/guides/run_base/v1/pose.json`
  (walk: `walk_base/v2/pose.json`; or `--stride <game px>` — delivered files have no pose.json beside them) attaches 8 gait cells to a
  registered sheet (floor y=870 -> anchor y, x=192 -> anchor x; `anims.run` + `runStride`); never convert gait strips with `sheets.py`.
  Deliveries: `art/inbox/gait/<sheet png stem>_<run|walk>` (.aseprite and/or `_a.png` + `_b.png`), checked by `receive.py gait/<stem>_<gait>`.
  Mannequins are refused (guides/ path, joints layer, frames matching a cloud skeleton draft). Rules: `art/README.md`.
- Sprite post-processing: `.claude/skills/sprite-gen/SKILL.md` — vendored `tools/sprite-gen`,
  **offline commands only**; no sprite-gen generation / server / rife / face-bake commands, no API keys there.
- NovelAI: `tools/art/novelai.py` may generate images **only when the user asks**, within the free tier
  (area <= 1024x1024, <= 28 steps, 1 image per call, `--max` 2 per run; no `--allow-paid` unless the user says so).
  The token is injected by the cloud proxy (or `NOVELAI_TOKEN` locally); never write it to files or logs.
  **NovelAI is for design drafts ONLY (owner decision): final game art always goes through GPT (the owner's PC session may refine it in Aseprite — see docs/pc_cloud_protocol.md).** Never request or
  register a NovelAI "final": `novelai.py` writes only `art/concepts/<id>/drafts/nai_*.png` (git-ignored) or a scratch
  `--outdir` and refuses `art/inbox/`, `assets/`, `art/requests/`; `sheets.py` refuses NovelAI images
  (`--allow-draft` is a test flag that always implies `--dry-run`).
- GPT handoff (battle sprites): `python3 tools/art/handoff.py` builds `art/requests/phase3/<id>/` (concept, posekit guides,
  `guide_strip.png` layout, README with the GPT prompt); rules in `art/requests/gpt_handoff_notes.md`; GPT works from `art/requests/GPT_STANDING.md` + `dot_queue.md` 「지금 차례」 (old per-item messages: `art/requests/archive/phase3_gpt_log.md`).
- Procedural pixel characters: `tools/pixelart/` (`python3 tools/pixelart/baren.py OUT_DIR`).
- Run skeleton draft: `python3 tools/pixelart/run8.py OUT_DIR --aseprite tools/art/ase_headless.sh` (8-frame mannequin, starting template only — the PC
  session makes the mannequin sequences, `check_skeleton.py` checks them; `art/requests/guides/SPEC.md`).
- Aseprite: never commit Aseprite binaries (EULA forbids redistribution). Build notes only.
- PC Aseprite session: the owner's Windows PC runs official Aseprite + aseprite-mcp (pinned, reviewed commit; setup and the
  5 denied tools in `tools/aseprite-mcp/README.md`). The PC session only writes `art/inbox/` on `art-inbox`
  (`<stem>.png` + `aseprite/<stem>.aseprite`; pose-skeleton guides: `guides/<id>/<id>.aseprite` only — the cloud exports the strips); this repo's
  cloud session receives (`tools/art/receive.py` → `check_delivery.py` + `sheets.py --dry-run`), registers and owns `dot_queue.md` statuses.
  Roles, branches, naming: `docs/pc_cloud_protocol.md`; the PC's instruction is `tools/aseprite-mcp/pc/CLAUDE.md` (versioned) + `art/requests/pc_notes.md`.
- Collaboration rules of the art loop (who decides what, cross-checks, single-pose checks): `art/requests/dot_queue.md` rules section;
  GPT's standing instruction `art/requests/GPT_STANDING.md`; skeleton guides `art/requests/guides/SPEC.md`.
- Owner policy: references (including third-party effect libraries or sprites) are for learning only — never ship someone else's
  finished assets or code in the game; generation/editing tools (Aseprite, sprite-gen offline) are fine.
