# C14 — roll 모드 귀환 결과를 출격 때 고정하기 (Codex)

## Why
GPT Q13 에서 나온 P1 이다. 이 문제는 C11 전부터 있었다.
- roll(확률 판정) 모드에서 귀환을 처리하기 전의 저장을 다시 열면, 같은 출격의 결과가 바뀐다.
- 예: 시드 17 은 실패, 139 는 성공, 1977 은 대성공.
- 원인은 `js/contract.js` `resolveMission` 의 결과 굴림이다(`Math.random()`, 393줄 근처). 다시 연 문서의 난수 상태를 따라간다.
- 전투 모드는 출격 때 굳힌 전투 시드를 쓰므로 영향이 없다(12/12 고정).

## Do
1. roll 모드에서 출격할 때 그 임무에 결과용 시드를 하나 정해 저장한다.
   - 예: `mission.rseed`. 세이브 솔트와 의뢰 id 에서 만들거나, 출격하는 순간 한 번 굴린다.
   - 귀환 판정(성공·실패 굴림, 사망 굴림 등 그 임무 결과에 쓰는 난수)은 이 시드로 만든 작은 결정적 난수열에서 뽑는다.
   - 세계 사건 같은 다른 난수 흐름은 건드리지 않는다.
2. 옛 저장에 `rseed` 가 없는 임무가 있으면 처음 불러올 때 한 번 정해 저장한다. 같은 저장을 다시 열어도 같은 결과가 나와야 한다.
3. 시험
   - Q13 재현(시드 428103, 3일 #15, 바렌 출격 → 구매 → 복원 → 다음 날)을 다시 돌린다. 브라우저 난수를 여러 개(예: 17/139/1977) 바꿔도 같은 결과가 나와야 한다.
   - `node --check`, `node tools/sim/battle.js 100` 은 miss=0 이어야 한다.
   - roll 봇 md5 는 **바뀐다**. 새 값과 함께 왜 바뀌는지 적는다(결과 난수 흐름이 바뀌어서).
     - 승패 분포가 그대로인지 보인다: `SIM_JSON=1 node tools/sim/bot.js 12 365` 요약의 완료·실패·대성공 비율을 전후로 비교한다.
     - 차이는 잡음 수준이어야 한다.
   - 전투 모드 봇 요약(`SIM_RESOLVE=battle node tools/sim/bot.js 12 365 --jobs 6`)은 그대로여야 한다.
