# C11 — Q4 화면 결함 고치기 (Codex)

## Why
GPT-QA 가 Q4 에서 관리 화면 결함 6건과 설계 문제 1건을 찾았다(`docs/agents/reports/gpt-qa.md` 「Q4」, 캡처 `shots/Q4/`).

**시작 전에 게임 브랜치 최신을 받는다.** 3단계 작업이 `js/game.js`, `js/ui.js`, `js/ui-tabs.js` 를 고치고 있다. 그 작업이 합쳐진 뒤의 코드 위에서 고쳐야 충돌이 적다.

## Do
1. 결함 Q4-01 ~ Q4-06 을 보고서의 「고칠 곳/제안」대로 고친다.
   - Q4-01 단원 행: 실제 버튼 또는 행 안의 상세 버튼을 둔다. Enter/Space 로 열리고, 닫으면 포커스가 같은 단원으로 돌아온다.
   - Q4-02 지도: 지도 옆에 지역 목록(select 또는 버튼 목록)을 두고, 캔버스 클릭과 선택 상태를 맞춘다.
   - Q4-03 긴 창: 열 때 맨 위에서 시작하고, 초점은 제목이나 창에 둔다.
   - Q4-04 400px 터치 대상: 「다음 날」「메뉴」, 장비·이동·해고, 닫기, 증축을 44px 이상으로 한다. 해고는 다른 버튼과 간격을 두어 떨어뜨린다.
   - Q4-05 길드 이름 입력: label 을 연결한다.
   - Q4-06 능력치 표시: 「능력 이름+수치」를 한 덩어리로 묶어 줄이 바뀌어도 떨어지지 않게 한다.
2. **총괄 결정 (11-27) — 저장:** 관리 조작을 하면 바로 저장한다. 대상은 증축, 구매·장착, 고용·해고, 배속, 이름 변경 등 게임 상태를 바꾸는 모든 조작이다.
   - 「다음 날」 자동 저장은 그대로 둔다.
   - 조작 뒤 새로고침해도 상태가 남아야 한다.
   - 이미 있는 저장 함수를 부르는 방식으로 하고, 저장 형식은 바꾸지 않는다.
   - 전투 결과 쪽 저장은 건드리지 않는다.
3. 시험을 돌린다.
   - `node --check` 로 모든 js 를 검사한다.
   - `node tools/sim/battle.js 100` 은 miss=0 이어야 한다.
   - `SIM_JSON=1 node tools/sim/bot.js 6 200 | md5sum` 은 지금 값과 같아야 한다. 화면만 고치니 같아야 정상이다. 다르면 이유를 적는다.
   - 1280×900 과 400×800 에서 각 결함을 다시 재현해 고쳐졌는지 캡처한다.

## Do not touch
전투 엔진(`js/battle.js`), 판정(`js/stats.js`, `js/muster.js`), 의뢰 출정 창, 에셋.
