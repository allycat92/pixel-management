# C21 — 예상 보정용 데이터 뽑기 (Codex, 측정만)

## Why
「한 부대 다듬기」 뒤에도 예상이 어긋나는 곳이 둘 남았다(`docs/plans/battle_stats/stage3_notes.md` 「One-company polish」 Open issues).
- **여러 부대 61~120일 「백중」:** 45% 로 조금 낙관적이다. 특히 원거리+격려 대장이 이끄는 부대(35~37%)와 여러 부대가 함께 가는 원정(34%)에서 그렇다.
- **보스:** 「우세」 이상으로 보내면 83% 만 이긴다. 목표는 85~90% 다.

지금 쌓인 데이터에는 대장의 「싸움 방식」만 있고 **어떤 대장인지**는 없어서 원인을 가를 수 없다. 총괄이 보정을 정할 수 있도록 데이터를 뽑아 준다. 주인 원칙이 「밸런싱은 CLI 가 시험하고, 총괄은 추출된 데이터로」다.

## Do
1. 전투 모드 봇에 **보는 의뢰를 모두 머리 없이 싸워 보는 수집기**를 만든다.
   - 위치: `tools/sim/` 의 새 스크립트 또는 `shadow.js` 의 새 옵션
   - 「One-company polish」 절에 있는 collect3/collect4 방식을 따른다. 그 스크립트들은 총괄 scratch 에 있어 저장소에는 없다. 보고서를 참고해 다시 만든다.
2. 전투마다 한 줄씩 CSV(또는 JSON lines)로 남긴다.
   - 필수 열: seed, day, 의뢰 종류(일반/보스/원정/이야기/결전), 별, 지형 규칙, 예상 R, 예상 단어, 실제 승패, 시간 초과 여부
   - 부대 정보: 부대 수, 부대별 대장 **key**(예: `tactician`), 대장 싸움 방식, 인원, 평균 레벨, 훈련병 수
   - 적 정보: 적 원형(archetype), 적 수, 보스 key
3. 수집 범위
   - 여러 부대 sensible 봇: 시드 세트 3개 × 12판 × 365일
   - 한 부대 human 봇: 「One-company polish」의 human 전략, 시드 세트 2개
4. 요약표를 만든다.
   - 대장 key 별 「백중」·「우세」 승률(n)
   - 원정 부대 수별 승률
   - 보스 key 별 승률
   - 61~120일 승률
5. 데이터 파일은 `data/C21/` 에 넣는다. 크면 gzip 으로 압축한다. 각 파일 20MB 이하로 한다.

## Do not touch
게임 코드의 계산(측정만 한다). `Stats.KN` 도 건드리지 않는다.

## Deliver
- 브랜치 `agent/codex` 에 올린다.
- 보고서 `## C21 — <날짜>` 를 쓴다. 요약표와 파일 설명을 넣는다.
- 이 줄을 REVIEW 로 바꾼다.
