# 공격 마네킹 · `atk__captain_ironwall` — 브리긴다 (탑 방패 밀치기)

공통 규칙은 `art/requests/guides/SPEC.md` (캔버스 3절, 레이어 4절, 관절 점 4절, **10절 = 동작 마네킹의 이름·납품·검사 수치**). 이 파일 하나만 읽고 끝낼 수 있게 적었다. 요청 2026-11-26 (클라우드).
초안은 없다 — **클라우드는 이 세트의 초안을 굽지 않는다**. **이 세트는 마네킹만**이다(시운전에서 GPT 띠를 내지 않는다).

## 왜 만드나 (주인 결정)
- 전투 동작을 4장면에서 **프레임 시퀀스**로 바꾼다 (`docs/plans/2026-11-26_motion_frames.md`). 공격 한 번 = 들어감 → 준비 멈춤 → 휘두름 중간 → **맞는 순간** → 지나침 → 돌아옴 → 자리 잡기.
- **마네킹 시퀀스는 PC 가 만든다** (주인: "마네킹 시퀀스도 pc하청으로"). 클라우드는 사양과 검사만. 스크립트로 지어도(걷기의 `walk8_pc.py` 처럼), 걷기·달리기 `.aseprite` 를 몸 틀로 써도 된다.
- **캐릭터마다 자기 방식으로 움직인다** (주인). 브리긴다는 병과 전사(`atk__class_warrior`)와 같은 검·방패 계통이라 **같은 틀이 되기 가장 쉬운 짝**이다.
  이 세트는 "같은 계통 두 캐릭터의 마네킹이 실제로 달라지는가"를 첫 관문에서 보여 주려고 넣었다(계획 0절·11절). 게임 크기 실루엣 IoU 가 0.8 을 넘으면 FAIL.

## 관절 목표 (머리 단위 → 원본 px, 머리 110)
- 가로: **x px = 170 + 110·x** (170 = 이 세트의 대기 엉덩이 열 → 전체가 x=39~340). 세로: **y px = 870 − 110·h**. 손은 바닥 위 실제 높이(`motion_chars.json` 의 at() 값에서 바꿈).
- 발목 높이 0.12 머리(평평). 뒷발목 −0.80 고정, 앞발목 +0.95 → 맞는 순간 +1.10 → 돌아옴 +1.02 → 자리 잡기 +0.95.
- 철퇴 각도: 수학 각도(0° 앞, 90° 위, 180° 뒤), 가까운 손에서 철퇴 머리 방향. **휘두름 중간 → 맞는 순간 사이 10° 미만**으로만 움직인다(철퇴가 "베는" 것으로 재지 않게 — 이 세트의 판정은 방패다).
- 먼 팔은 팔꿈치를 **아래로** 접어 방패를 받친다(팔꿈치가 방패 앞으로 튀어나오지 않게).

## 이 캐릭터만의 것 (병과 전사와 다른 점)
- **맞는 순간 = 방패**. 전사는 방패 치기가 휘두름 중간이고 맞는 순간은 칼이다. 브리긴다의 방패 앞면은 맞는 순간에 가장 멀리 나가고(전사는 휘두름 중간), 철퇴는 끝까지 뒤에 남는다.
- 더 낮고 무겁다: 준비 엉덩이 1.22(전사 1.28), 넓은 발(−0.80 / +0.95), 맞는 순간 **앞발을 내딛는다**(전사는 두 발 고정).
- 탑 방패 0.40 x 1.30(세운 벽) — 전사는 둥근 방패 0.68 x 0.90. 철퇴는 머리 높이 뒤(전사 칼은 엉덩이 옆 뒤-아래).
- 시간이 다르다: 준비 170, 맞는 순간 80, 지나침 80(전사 160 / 70 / 90). 대기 숨쉬기는 아주 작게(무거운 갑옷, idleTempo 1.25 — 이 세트에는 대기 없음).
- 클라우드 어림(같은 몸 위 두 표의 게임 크기 실루엣 IoU): hold 0.76, contact 0.71 — 기준 0.8 이하. **hold 가 0.8 에 가깝다**: 고칠 때 방패를 더 낮고 넓게, 철퇴를 더 높게 두는 쪽으로(전사와 멀어지게) 고친다.

## `motion_chars.json` 덮어쓰기와 다른 곳 (클라우드가 고친 이유 — 클라우드가 JSON 에 되돌려 넣는다)
- hold 엉덩이 (−0.18, 1.24) → **(−0.36, 1.22)**, 기울기 0.20 → **0.10**, contact 기울기 0.26 → **0.32**: 검사는 준비에서 머리가 두 발목 가운데보다 **뒤**, 맞는 순간 **앞**, 그 사이 100px 이상을 요구한다. 원래 값 그대로면 준비의 머리가 이미 발 가운데 앞 +19px, 이동 57px 로 FAIL(SPEC 10.4 의 시험).
- 발목 −1.10(posekit 대기) → **−0.80**: 맞는 순간 엉덩이(+0.36, 1.18)에서 −1.10 까지는 다리가 닿지 않는다. 앞발 내딛기 footF (1.15, 0.12) → 0.95 에서 **1.10**(같은 +0.15 머리).
- 철퇴 손 hold (−0.55) → **−0.45**, 방패 손 contact 1.20 → **1.30** + 팔꿈치 아래로: 원래 값이면 7프레임을 합친 폭이 320px 를 넘고, 방패가 먼 어깨에 너무 가까워 팔꿈치가 방패 앞으로 튀어나온다.
- hold 의 방패를 「땅에 박은 자세」(특기 설명)로 내리지 않았다: 같은 파일의 "아랫단 바닥 위 100px 이상" 규칙을 따랐다. 주인이 땅에 박은 방패를 원하면 클라우드가 이 줄을 고친다.

## 시작하는 법 (PC 가 고른다)
1. **스크립트(권장)**: `walk8_pc.py` 처럼 `tools/pixelart/posekit.py`(`pk.Body(4.0)`, `pk.build(pose, B, 'none')`) + `tools/pixelart/walk8.py`(`draw`, `frame_layers`, `floor_row`)로 표를 포즈로 넣어 부위 레이어 + `joints` 점을 쓴다.
   포즈 키: `hip=(x, h)`, `lean`, `footN=(−0.80, 0.12)`, `footF=(x, 0.12)`, `handN=('p', x, h)`, `handF=('p', x, h)`, `elbF=(−0.3, 1.0)`(먼 팔꿈치를 아래로), `faN=faF=0`.
   `frame_layers` 는 엉덩이 0 을 x=192 에 두므로 모든 x 에서 (192−170)/110 = 0.20 을 빼고 그린다. 방패·철퇴는 스크립트에서 위 크기로 그린다.
   실행 예: `uv run --no-project --with pillow --with numpy python ~/Documents/pm-pc-scratch/mannequin_pc.py . ~/Documents/pm-pc-scratch/atk__captain_ironwall`. 조립은 걷기 v2 때처럼 aseprite-mcp 도구로(프레임 시간·`attack` 태그·`joints` 숨김).
   전사 세트와 같은 스크립트를 쓰면 표만 바꿔 돌릴 수 있다 — 그래도 **두 세트의 프레임이 같아지지 않게** 표의 값을 그대로 쓴다.
2. **몸 틀**: `art/requests/guides/walk_base/v2/walk_base.aseprite` 또는 `run_base/v1/run_base.aseprite` 의 부위 레이어를 옮겨 자세를 만든다. 뼈 길이(넓적다리·정강이 89.65, 위팔 68.2, 아래팔+손 71.5px)는 바꾸지 않는다.
3. Aseprite 에서 **재생해 본다**(ms 그대로). 방패가 "쾅" 하고 부딪히는 한 프레임이 읽히는지는 PC 만 볼 수 있다.

  **맞는 순간에 방패 앞면이 가장 멀리 나가지 않음(다른 프레임보다 2px 이상)** · 휘두름 중간 → 맞는 순간 실루엣 변화 15% 미만 · 돌아옴이 지나침보다 첫 프레임에서 더 멂.

- 경고: 방패 앞면 이동(준비 → 맞는 순간)이 55px 미만 · 맞는 순간 → 지나침 실루엣 35% 초과 · 지나침에서 엉덩이가 뒤로 · 이웃 프레임 변화 8% 미만 · 철퇴 60% 미만이 몸 밖 · 그림이 x=32~351 밖.
