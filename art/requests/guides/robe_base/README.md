`check_skeleton.py` 에 이 세트의 모드(`robe`)가 아직 없다 — 아래 「자체 검사」의 임시 명령과 기대 출력대로 본다.

**왜 만드나 (주인 2026-11-26)**: "달리기(이동)에 대해 3가지 부류를 정하고 싶어. 경량, 중량, 로브. 펑퍼짐한 천 복장을 입고 뛰는것도 좀 부자연스러울거고 …"
→ 전투 이동은 세 부류다: **경량** = 받아들인 달리기(`../run_base/v2/`), **중량** = `../heavy_base/`, **로브** = 이 세트.
로브는 발목까지 오는 헐렁한 천옷(마법사·사제 등)이다. 여전히 **그 몸이 낼 수 있는 가장 빠른 이동**(주인: 전투 이동은 달리기)이지 산책이 아니다 —
그러나 **뜨지 않고**(늘 한 발은 땅), **서 있고**(6~7°), **무릎을 거의 들지 않는다**(자락이 다리를 가린다). 짧고 잦은 걸음으로 **미끄러지듯 서두른다.**
**누가**: 마네킹 시퀀스는 PC(Aseprite)가 만든다(주인 "마네킹 시퀀스도 pc하청으로"). 아래 초안은 클라우드가 수치표로 구운 **출발점**이다.

## 느낌 (말로)
긴 치마를 입고 서두르는 사람 — 상체는 곧게, 발은 자락 밑에서 **종종** 빠르게 나가고, 엉덩이는 거의 오르내리지 않는다(미끄러짐).
- 보이는 것은 **자락의 흔들림과 그 밑의 발끝**이다. 자락이 무릎·정강이를 가린다(자락 아랫단이 바닥 위 40~47px — SPEC 7절 "38px 이상, 발끝이 보이게").
- 앞자락은 앞으로 나가는 다리에 **바로** 밀려 나가고, 다리가 물러난 뒤에도 **한 프레임 늦게** 돌아온다. 뒷자락도 같다(뒤로 간 다리에 밀렸다가 한 프레임 늦게).
  자락의 높이(아랫단)도 엉덩이보다 한 프레임 늦게 오르내린다.
- 들린 발은 바닥에서 5~11px 만 뜬다(걷기 30~36px). 무릎을 높이 들면 자락이 무릎 모양으로 솟아 "천 속에서 뛴다" 가 된다 — 주인이 부자연스럽다고 한 것.
- 팔은 작고 빠르게 흔든다(팔꿈치 56~64°, 위팔 ±26°) — 서두름은 팔과 박자(90ms)로 보인다.

## 수치 (초안 `draft/` — 원본 px, 머리 110 기준 → 게임 px 는 x0.1654)
- **한 걸음 = 몸이 한 걸음에 가는 거리 145px → 게임 24.0px (`runStride`).** 경량 275px(45.5)의 약 절반, 걷기(143)와 비슷하지만 **박자가 걷기의 1.33배**(90ms 대 120ms).
  몸은 프레임마다 36.3px 간다. 디딘 발의 **발끝**은 그 발이 땅에 있는 다섯 프레임(G1 → G2 → G3 → G4 → G5 의 뒷발)에서 프레임마다 36px(±3)씩 물러난다.
  초안 발끝 x(엉덩이 기준): 가까운 발 91 → 55 → 19 → -17 → -53, 먼 발 96 → 60 → 24 → -14 → -50 (물러남 36~38px).
  (걷기 검사기의 "닿을 때 발목~발목"으로 재면 141px — 뒷발이 발끝으로 굴러 있어서다)
- 엉덩이 높이(검사기가 재는 엉덩이 중심): 닿음 182 · 내려앉음 180 · 지나감 188 · 밀어냄 188px → **오르내림 7px(게임 1.2px)** — 경량(5.5px)처럼 거의 평평, 걷기(12~16px)보다 작다.
- 상체 기울기(엉덩이 → 목 점): 6.8° · 7.3° · 6.2° · 6.2° (수치표 0.07~0.09rad). 목 점 이동 2.3px.
- 무릎(앞발 / 뒷발): 닿음 23° / 18°(G5 34° / 27°), 내려앉음 45° / 49°, 지나감 36° / 35°(디딘 다리 — 조금 굽힌 미끄러짐), 밀어냄 28° / 26°. 자락 밑이라 거의 안 보인다.
- 들린 발 바닥 높이: 내려앉음 7~10px, 지나감 9~11px, 밀어냄 5px. 지나가는 무릎은 디딘 무릎보다 17~27px 앞(걷기 38px 이상) — 무릎을 들지 않는다.
- 자락(`cloth_front`, `pose.json` 의 `hem` = 수치표 값): 아랫단(레이어의 맨 아래 픽셀, 외곽선 포함) 바닥 위 41~48px(엉덩이 높이를 한 프레임 늦게 따른다: 이전 프레임 엉덩이 − 1.245머리),
  아랫단 위 20줄 안의 앞 끝 +56~+79px · 뒤 끝 -61~-93px(엉덩이 기준, 외곽선 포함). 두 무릎 점은 모든 프레임에서 자락 안. 이웃 프레임 사이 자락 실루엣 차이(게임 크기) 7~11%. 다리가 미는 만큼 바로 나가고(정강이·무릎 중심선에서 22px 바깥), 물러날 때는 이전 프레임의 자리에 한 프레임 머문다.
  밀려 나간 모서리는 그만큼 살짝 들린다(앞 0~9px, 뒤 1~11px).
- 팔: 디딘 쪽 팔 -22/58 → -26/62 → -8/60 → +12/58, 반대쪽 거울. 먼 팔은 어깨가 그림에서 0.7머리 앞이라 더 뒤로(-28 … +10). 손의 앞뒤 이동(어깨 기준) 가까운 손 12~101px, 먼 손 -3~81px.
- 시간: **한 프레임 90ms**(8프레임 720ms, 1분에 167걸음). 이 속도에서 발이 붙어 있으려면 몸이 초당 67px(게임) 가야 한다.
  게임은 그려진 칸을 **간 거리로** 넘긴다(SPEC 9절): 전사 1배속 코드 보폭 약 20.5px 이면 한 칸 약 83ms, 그려진 보폭 24.0px 과의 차이로 **디딘 발 미끄럼 칸마다 약 0.9px**(경량 약 6px).
- 그림은 x=32~351 안, posekit 경고 0.

## PC(Aseprite)가 할 일
1. 초안을 납품 폴더로 복사한다: `draft/robe_base.aseprite` → `../pixel-management-inbox/art/inbox/guides/robe_base/robe_base.aseprite`.
   Aseprite 로 열어 **90ms 로 재생**하고 `draft/robe_base_vs_run.gif` 와 견준다. 재생해서 **"긴 옷을 입고 서두른다"** 로 읽히는지(천 속에서 뛰지 않고, 산책처럼 느리지 않게)는 PC 만 볼 수 있다.
2. 클라우드가 본 다듬을 곳(초안의 솔직한 약점):
   - **자락 모양이 딱딱하다**: 초안의 자락은 허리에서 아랫단까지 곧은 사다리꼴(모서리 10개)이다. 천은 앞 다리에 걸린 곳이 둥글게 밀리고, 뒤로는 주름이 끌린다 —
     `cloth_front` 의 **외곽만** 손으로 다듬는다(아랫단 높이 38px 이상은 지킨다, 다리 레이어는 그대로).
   - **한 프레임 늦음이 반쪽에서만 보인다**: G1 → G2 는 자락이 같은 모양(머묾), G3 에서 좁아진다. 재생해서 늦음이 "뻣뻣함"으로 보이면 G2 의 자락을 G1 과 G3 사이로 조금 옮겨도 된다(12px 이상 차이 = 게임 2px 이 보이는 최소).
   - **G1 과 G5 가 조금 다르다**: 먼 발(장화가 10% 큼)과 가까운 발의 크기 차이로 앞자락이 72 / 77px. 괜찮으면 그대로 둔다.
   - **팔**: 맨손 마네킹이다. 지팡이를 드는 직업은 SPEC 7절(마법사·사제: 가까운 손에 지팡이, 먼 팔 50%)을 이 위에 얹는다.
3. SPEC 3절(캔버스)·4절(레이어)을 지킨다. 뼈 길이는 바꾸지 않는다. **팔다리를 옮기면 `joints` 레이어의 그 관절 점도 같이 옮긴다**(`joints` 는 숨긴 채 저장).
   레이어 이름·순서(`cloth_front` 는 torso 와 head 사이)·384x1024·8프레임·90ms 는 그대로. 엉덩이 중심은 모든 프레임에서 x=192 (±1). 지켜야 하는 것:
   - **어느 프레임이든 한 발은 y=870**(뜨는 프레임 없음). G1·G5 는 **두 발 모두** y=870. G2~G4·G6~G8 의 다른 발은 바닥 위 4px 이상(끌리지 않게), 16px 이하(무릎을 들지 않게).
   - 디딘 발 **발끝**은 다섯 프레임 동안 프레임마다 같은 거리(36px, ±3)씩 물러난다. 한 걸음 145px ±10 — 바꾸려면 먼저 묻는다.
   - 자락 아랫단은 모든 프레임에서 바닥 위 38px 이상, 두 무릎 점은 모든 프레임에서 자락(`cloth_front`) 안에 있다.
4. 자체 검사 (이 저장소 폴더에서). **지금 `check_skeleton.py` 에는 `robe` 모드가 없다**(`--pose draft/pose.json` 만 주면 `unknown gait "robe"` 로 FAIL).
   그때까지는 걷기 규칙으로 공통 항목(캔버스·레이어 — `cloth_front` 는 SPEC 4절 이름이라 통과 — 관절 점·뼈 길이·엉덩이 x=192·머리)만 확인한다:
   `uv run --no-project --with pillow --with numpy python tools/art/check_skeleton.py ../pixel-management-inbox/art/inbox/guides/robe_base/robe_base.aseprite --gait walk --base art/requests/guides/robe_base/draft/robe_base.aseprite`
   초안을 그대로 재면 `RESULT: PASS (9 warning(s))` 이고 경고는 모두 의도된 것이다 — **무시**: `frame duration differs … 120 ms`(90ms 가 맞다) · `bob 7.0 px, SPEC asks 12-16` ·
   `W3/W7 (passing): the supporting knee is bent 36/35 deg` · `… the lifted foot is 9/11 px` · `… the lifted knee leads … 27/17 px` · `W6: the forward hand is 7 px outside the torso`.
   그 밖의 `FAIL`/`WARN` 이 있으면 고친다. 자락 아랫단 높이와 무릎 점이 자락 안인지는 아직 검사기가 재지 않는다 — Aseprite 에서 눈으로 본다.
   `robe` 모드가 생기면 `--gait walk` 를 빼고 `--pose art/requests/guides/robe_base/draft/pose.json` 을 붙인다(그때 이 README 를 고친다).
5. 납품: art-inbox `art/inbox/guides/robe_base/robe_base.aseprite` **하나**. `art/inbox/` 밖은 건드리지 않는다.
   NOTES 절 「뼈대 — 로브 이동 (Aseprite)」: 바꾼 프레임과 수치(px), 자락을 어떻게 다듬었는지, 검사 줄(위의 의도된 줄 포함), 재생해 본 느낌. 커밋 `Touch up guide robe_base (Aseprite)`.

## 검사기에 넣을 기준 (도구 담당 — `check_skeleton.py --gait robe`, `pose.json` 의 `"gait": "robe"`; PC 는 읽기만)
공통 항목(캔버스·레이어·관절 점·뼈 길이 ±2·딱 떨어지는 가장자리·엉덩이 x=192 ±1·머리 레이어·머리 쪼임 4px·머리 기울기 8°)은 그대로. 프레임 이름 G1~G8.
걸음 항목은 `heavy` 모드와 같은 틀(뜸 없음·닿음에서 두 발·발끝 다섯 프레임 물러남·좌우 바꿈)에 값만 다르다:
- **실패**: 어느 프레임이든 두 발이 모두 y=870 에서 떨어짐 · y=870 아래 픽셀 · G1·G5 에서 두 발 중 하나라도 y=870 이 아님 · G2~G4·G6~G8 에서 디딘 발이 y=870 이 아님 ·
  디딘 발끝이 다섯 프레임 동안 프레임마다 step/4 ±3px 씩 물러나지 않음 · step 이 `step_px`(145) ±10px 밖 · G(i+4) 가 G(i) 의 좌우 바꿈이 아님(엉덩이 ±1, 발목 x ±2, 발목 높이 ±4) ·
  **`cloth_front` 레이어가 없거나 비었음 · 그 맨 아래 픽셀이 바닥 위 38px 미만(SPEC 7절) · 무릎 점(kneeN·kneeF)이 `cloth_front` 의 불투명 픽셀 위에 있지 않음(자락이 무릎을 가린다)**.
- **경고** (초안 값): 기울기 4~10° 밖(6.2~7.3) · 기울기 변화 4° 초과(1.1) · 오르내림 12px 초과(7.1 — 미끄러짐) · 내려앉음의 엉덩이가 그 반쪽에서 가장 낮지 않음(±2) ·
  들린 발 바닥 4px 미만(끌림) 또는 16px 초과(무릎을 든다; 초안 5~11) · 자락 아랫단 38~52px 밖(41~48) ·
  **자락의 늦음**: 내려앉음(G2·G6)의 `cloth_front` 앞 끝·뒤 끝 x(아랫단 위 20줄 안의 맨 앞·맨 뒤 픽셀)가 닿음(G1·G5)과 4px 넘게 다름(초안 0 — 한 프레임 머문다) ·
  이웃 프레임 사이 `cloth_front` 실루엣(게임 크기) 차이가 한 바퀴 내내 5% 미만(자락이 안 움직인다; 초안 7~11%) · 팔꿈치 45~80° 밖(56~64) · 프레임 시간 ≠ `nominal_ms` 90 ·
  이웃 프레임 실루엣 차이 8% 미만(초안 14~22%).
- 띠 검사: `check_delivery.py` 를 `--flight-slots` **없이**(모든 칸의 맨 아래 픽셀이 y=870). `receive.py` 는 `pose.json` 의 gait 가 `run` 이 아니면 이미 그렇게 한다.
- `receive.py guides/robe_base` 는 `draft/` 의 `pose.json` 을 `--pose` 로 넘긴다 — `robe` 모드가 생기기 전에는 `unknown gait` 로 FAIL 한다(예상된 것).
