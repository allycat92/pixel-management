## 느낌 (말로)
긴 옷을 입고 **목적지로 서둘러 가는** 사람 — 상체를 조금 앞으로(7°) 실어 몸이 먼저 나가고, 발은 자락 밑에서 **종종** 빠르게 나가며(1분에 156걸음),
엉덩이는 거의 오르내리지 않는다(미끄러짐, 5px). 느긋한 산책이 아니다.
- 보이는 것은 **자락의 흔들림과 그 밑의 발끝**이다. 자락이 무릎·정강이를 가린다(자락 아랫단이 바닥 위 41~46px — SPEC 7절 "38px 이상, 발끝이 보이게"). 두 무릎 점은 모든 프레임에서 자락 안.
- 앞자락은 앞으로 나가는 다리에 **바로** 밀려 나가고, 다리가 물러난 뒤에도 **한 프레임 늦게** 돌아온다(내려앉음 G2·G6 은 닿음의 자락 모양 그대로). 뒷자락도 같다.
  자락의 높이(아랫단)도 엉덩이보다 한 프레임 늦게 오르내린다.
- 들린 발은 바닥에서 5~10px 만 뜬다(걷기 30~36px). 무릎을 높이 들면 자락이 무릎 모양으로 솟아 "천 속에서 뛴다" 가 된다 — 주인이 부자연스럽다고 한 것.
- **팔은 몸에 붙인다**: 팔꿈치 72~76° 로 접어 손을 허리 높이(177~218px, 엉덩이 177~182 위)에 둔다 — 지팡이를 쥐거나 자락을 잡은 손. 걸음 따라 작게 흔들린다
  (손의 앞뒤 이동 33~36px, 경량 달리기 v2 는 107~111px). 서두름은 기울기와 박자로 보인다.

## 시간 — 게임이 실제로 잡는 칸 시간
게임(`js/battle.js` `runCells`)은 중량·로브의 그려진 이동 칸을 **디딘 채로** 넘긴다: 한 칸 = 몸이 그려진 보폭의 1/4(ds/4) 를 가는 동안. 유닛의 빠르기는 그대로다
(주인 결정: 발 미끄럼은 "그대로 둠 (B만)"). 1배속 유닛 빠르기 약 58 게임 px/초 이면 **한 칸 = (22.2 / 4) / 58 = 96ms**(8칸 768ms, 1분에 156걸음 — 중량 101ms 보다 조금 잦다).
이 초안의 프레임 시간이 96ms 인 까닭이고, **느낌은 이 96ms 에서 본다.** 느린 유닛·1.5배 우두머리 시트는 칸마다 같은 비율로 길어진다.
같은 빠르기의 경량 달리기는 닿음·내려앉음 196ms, 밀어냄·뜸 98ms(보폭 45.5px).

## PC(Aseprite)가 할 일
1. 초안을 납품 폴더로 복사한다: `draft/robe_base.aseprite` → `../pixel-management-inbox/art/inbox/guides/robe_base/robe_base.aseprite`.
   Aseprite 로 열어 **96ms 로 재생**하고 `draft/robe_base_vs_run.gif` 와 견준다. 재생해서 **"긴 옷을 입고 서둘러 간다"** 로 읽히는지(천 속에서 뛰지 않고, 산책처럼 느긋하지 않게)는 PC 만 볼 수 있다.
2. 클라우드가 본 다듬을 곳(초안의 솔직한 약점):
   - **자락 모양이 딱딱하다**: 초안의 자락은 허리에서 아랫단까지 곧은 사다리꼴(모서리 10개)이다. 천은 앞 다리에 걸린 곳이 둥글게 밀리고, 뒤로는 주름이 끌린다 —
     `cloth_front` 의 **외곽만** 손으로 다듬는다(아랫단 높이 38px 이상, 두 무릎 점은 자락 안, 다리 레이어는 그대로).
   - **한 프레임 늦음**: G1 → G2 는 자락이 같은 모양(머묾), G3 에서 좁아진다. 재생해서 "뻣뻣함"으로 보이면 G2 의 자락을 G1 쪽에 가깝게(4px 안) 조금만 옮긴다.
   - **G1 과 G5 가 조금 다르다**: 먼 발(장화가 10% 큼)과 가까운 발의 크기 차이로 앞자락이 71 / 77px. 괜찮으면 그대로 둔다.
   - **팔**: 맨손 마네킹이다. 지팡이를 드는 직업은 SPEC 7절(마법사·사제: 가까운 손에 지팡이, 먼 팔 50%)을 이 위에 얹는다 — 손 높이(허리)와 작은 흔들림은 지킨다.
3. SPEC 3절(캔버스)·4절(레이어)을 지킨다. 뼈 길이는 바꾸지 않는다. **팔다리를 옮기면 `joints` 레이어의 그 관절 점도 같이 옮긴다**(`joints` 는 숨긴 채 저장).
   레이어 이름·순서(`cloth_front` 는 torso 와 head 사이)·384x1024·8프레임·96ms 는 그대로. 엉덩이 중심은 모든 프레임에서 x=192 (±1). 아래 「검사 기준」의 실패 항목을 지킨다.
4. 자체 검사 (이 저장소 폴더에서):
   `python3 tools/art/check_skeleton.py ../pixel-management-inbox/art/inbox/guides/robe_base/robe_base.aseprite --gait robe --pose art/requests/guides/robe_base/draft/pose.json`
   (`robe` 모드가 들어가 있다 — 초안 그대로면 RESULT: PASS 경고 0. `--gait walk` 로 대신 검사하지 않는다.)
5. 납품: art-inbox `art/inbox/guides/robe_base/robe_base.aseprite` **하나**. `art/inbox/` 밖은 건드리지 않는다.
   NOTES 절 「뼈대 — 로브 이동 (Aseprite)」: 바꾼 프레임과 수치(px), 자락을 어떻게 다듬었는지, 검사 줄, 96ms 로 재생해 본 느낌. 커밋 `Touch up guide robe_base (Aseprite)`.

- 로브 캐릭터의 이동 프레임은 **`anims.run`** 으로 붙인다(전투 이동 = 달리기 칸). `add_gait.py <시트> --gait run --src … --pose art/requests/guides/robe_base/draft/pose.json`
