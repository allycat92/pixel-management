## 왜 만드나 (주인 결정)
- 전투 동작을 4장면(대기·준비·타격·피격)에서 **프레임 시퀀스**로 바꾼다 (`docs/plans/2026-11-26_motion_frames.md`). 공격 한 번 = 들어감 → 준비 멈춤 → 휘두름 중간 → **맞는 순간** → 지나침 → 돌아옴 → 자리 잡기.
- **마네킹 시퀀스는 PC 가 만든다** (주인: "마네킹 시퀀스도 pc하청으로"). 클라우드는 이 사양과 검사만 맡는다. 자세는 PC 가 스크립트로 지어도 되고(걷기 때의 `walk8_pc.py` 처럼), 걷기·달리기 `.aseprite` 를 몸 틀로 써도 된다.
- **캐릭터마다 자기 방식으로 움직인다** (주인). GPT 는 마네킹을 IoU 0.64~0.73 으로 따라 그리므로, 마네킹이 같으면 그림도 같아진다. 같은 검·방패 계통인 브리긴다(`atk__captain_ironwall`)와 **같은 프레임이 되면 안 된다** — 아래 「이 캐릭터만의 것」.
- 이 시트는 전사뿐 아니라 성기사·수호기사·검성·검신·광전사·성전사도 쓴다. 그래서 한 흐름에 두 박자를 넣었다: 휘두름 중간 = **방패 치기**, 맞는 순간 = **방패 가장자리 아래로 칼이 낮게 벰** (계획 1절 S6).

## 이 캐릭터만의 것 (브리긴다와 다른 점)
- **두 박자**: 방패는 휘두름 중간에 얼굴 높이로 가장 멀리 나가고(먼 손 x +0.95), 칼은 맞는 순간에 방패 **아래로** 지나간다. 브리긴다는 방패 자체가 맞는 순간이다(방패 밀치기).
- 칼: 준비에서 **엉덩이 뒤 낮은 손**에서 등 뒤로 비스듬히 세우고(120°), 뒤-아래로 떨어졌다가 앞으로 낮게 벤다 — 한 바퀴 도는 큰 칼질. 브리긴다의 철퇴는 **어깨 높이 손**에서 뒤로 겨눈 채(140°) 끝까지 돌지 않는다.
- 방패: 둥근 방패(0.68 x 0.90), 몸 앞 가슴~얼굴 높이. 브리긴다는 바닥 위 1.5 머리까지 내려오는 탑 방패.
- 발: 어깨너비보다 조금 좁게(−0.90 / +0.80), 두 발 모두 고정 — 브리긴다는 맞는 순간 앞발을 +0.15 머리 내딛는다.
- 키: 준비 엉덩이 1.32·맞는 순간 1.24(꼿꼿이 방패 뒤, 기울기 거의 0). 브리긴다는 1.16 · 1.12 로 훨씬 낮다.
- 닮음(클라우드가 지은 두 세트, `node tools/art/requests.js --motion` 의 정렬 IoU, 게임 크기): **hold 0.749, contact 0.720** — 기준 0.8 이하. 0.8 을 넘으면 FAIL 이니, 고칠 때 둘이 가까워지지 않게 한다(전사는 높게·칼은 뒤 위로, 브리긴다는 낮게).

## `motion_chars.json` 과의 관계
- `chars["sheet/class/warrior"].mannequin.overrides` 의 hold·swing·contact·follow 는 **이 표와 같은 값**이다(2026-11-26e, at() 단위로 적음). 예전 값과 다른 곳과 이유:
  - hold 엉덩이 (−0.22, 1.30)·기울기 0.12 → **(−0.30, 1.32)·0.04**: 검사는 준비에서 머리가 두 발목 가운데보다 **뒤**, 맞는 순간 **앞**, 그 사이 100px 이상 이동을 요구한다. 예전 값이면 hold 의 머리가 발 가운데 앞 +2px, 이동 76px 로 FAIL 이었다.
  - 발목 −1.10 / +1.00(posekit 대기 폭) → **−0.90 / +0.80**: 맞는 순간 엉덩이에서 뒷발목 −1.10 까지는 다리 길이(1.63 머리)보다 멀어 닿지 않는다.
  - hold 칼 190°(엉덩이 옆 뒤) → **120°(엉덩이 뒤 낮은 손에서 위-뒤)**: 엉덩이 옆 뒤로 겨눈 칼은 뒷다리·엉덩이 위에 겹쳐 19% 만 몸 밖이었다(경고). 칸 폭(320px) 안에서 60% 이상 보이는 자리는 등 뒤 위뿐이다.
  - 맞는 순간 손 x 1.15 → **0.75**, 칼 1.35 머리(posekit) → **0.85 머리**: 원래 값으로는 7프레임을 합친 폭이 384px 칸을 넘는다.

## 시작하는 법 (PC 가 고른다)
1. **스크립트(권장)**: 걷기 때 `walk8_pc.py` 처럼 `tools/pixelart/posekit.py` 몸(`pk.Body(4.0)`, `pk.build(pose, B, 'none')`)과 `tools/pixelart/walk8.py` 의 그리기·레이어 나누기(`draw`, `frame_layers`, `floor_row`, 발을 바닥에 맞추는 `settle`)를 불러,
   위 표를 포즈로 넣고 부위 레이어 PNG + `joints` 점을 프레임마다 쓴다. 포즈 키: `hip=(x, h)`, `lean`, **`tilt=lean/2`**, `footN=(−0.90, 0.12)`, `footF=(0.80, 0.12)`, `toeN=0.85`,
   `handN=('p', x, h)`, `handF=('p', x, h)`, `faN=faF=0`(swing·contact 만 **`faN=15`** — 뒤꿈치가 들리고 발끝은 제자리).
   `faN` 을 15° 넘게 주면 posekit 은 발목을 축으로 발을 돌려 발끝이 앞으로 밀린다(25° 에서 4px → FAIL). 더 들고 싶으면 발끝을 축으로 돌린다(발목을 올리고 그만큼 앞으로).
   `frame_layers` 는 엉덩이 0 을 x=192 에 둔다 — 이 세트는 x=170 이 0 이므로 모든 x 에서 (192−170)/110 = 0.20 을 빼고 그리면 된다. 칼·방패 소품은 스크립트에서 위 크기대로 그린다.
   실행: `uv run --no-project --with pillow --with numpy python ~/Documents/pm-pc-scratch/mannequin_pc.py . ~/Documents/pm-pc-scratch/atk__class_warrior` (이 저장소 폴더에서, 스크립트는 스크래치 폴더에).
   레이어 PNG 로 `.aseprite` 를 조립하는 것은 걷기 v2 때와 같은 방법(aseprite-mcp 도구)으로. 프레임 시간·`attack` 태그·`joints` 숨김을 표대로.
2. **몸 틀**: `art/requests/guides/walk_base/v2/walk_base.aseprite` 나 `art/requests/guides/run_base/v2/run_base.aseprite` 를 스크래치에 복사해 부위 레이어(팔·다리·몸통·머리, 같은 뼈 길이·관절 점)를 옮겨 자세를 만든다. 뼈 길이는 바꾸지 않는다(넓적다리·정강이 89.65px, 위팔 68.2, 아래팔+손 71.5, ±2px 넘으면 FAIL).
3. 어느 쪽이든 Aseprite 에서 **재생해 본다**(ms 그대로, 양파 껍질). 클라우드는 정지 수치만 맞췄다 — 맞는 순간이 "딱" 하고 읽히는지는 PC 만 볼 수 있다.
