# 공격 마네킹 · `atk__class_warrior` — 일반 병과 전사 (방패 치기 → 칼 베기)

공통 규칙은 `art/requests/guides/SPEC.md` (캔버스 3절, 레이어 4절, 관절 점 4절, **10절 = 동작 마네킹의 이름·납품·검사 수치**). 이 파일 하나만 읽고 끝낼 수 있게 적었다. 요청 2026-11-26 (클라우드).
초안은 없다 — **클라우드는 이 세트의 초안을 굽지 않는다** (아래 「왜」).

## 왜 만드나 (주인 결정)
- 전투 동작을 4장면(대기·준비·타격·피격)에서 **프레임 시퀀스**로 바꾼다 (`docs/plans/2026-11-26_motion_frames.md`). 공격 한 번 = 들어감 → 준비 멈춤 → 휘두름 중간 → **맞는 순간** → 지나침 → 돌아옴 → 자리 잡기.
- **마네킹 시퀀스는 PC 가 만든다** (주인: "마네킹 시퀀스도 pc하청으로"). 클라우드는 이 사양과 검사만 맡는다. 자세는 PC 가 스크립트로 지어도 되고(걷기 때의 `walk8_pc.py` 처럼), 걷기·달리기 `.aseprite` 초안을 몸 틀로 써도 된다.
- **캐릭터마다 자기 방식으로 움직인다** (주인). GPT 는 마네킹을 IoU 0.64~0.73 으로 따라 그리므로, 마네킹이 같으면 그림도 같아진다. 같은 검·방패 계통인 브리긴다(`atk__captain_ironwall`)와 **같은 프레임이 되면 안 된다** — 아래 「이 캐릭터만의 것」.
- 이 시트는 전사뿐 아니라 성기사·수호기사·검성·검신·광전사·성전사도 쓴다. 그래서 한 흐름에 두 박자를 넣었다: 휘두름 중간 = **방패 치기**, 맞는 순간 = **방패 가장자리 아래로 칼이 낮게 벰** (계획 1절 S6).

## 납품 (모든 마네킹 세트가 지키는 약속)
- art-inbox **`art/inbox/guides/atk__class_warrior/atk__class_warrior.aseprite` 하나**. 띠·프레임 PNG·GIF 는 올리지 않는다(클라우드가 이 파일에서 프레임마다 뽑는다).
  자세를 스크립트로 지었으면 그 스크립트를 같은 폴더에 `mannequin_pc.py` 로 함께 올린다(SPEC 1절. 수령 도구가 "ignored" 라고 적는 것은 정상 — 프레임 출처가 아니라는 뜻).
- 한 프레임 384x1024, Background 완전한 #FF00FF, 바닥 y=870, 머리 110px(4등신), 오른쪽을 본다.
- 레이어(아래 → 위, SPEC 4절 순서): `Background` · `arm_far` · `shield` · `leg_far` · `leg_near` · `torso` · `head` · `weapon_front` · `arm_near` · `joints`(숨김).
  이 밖의 이름은 FAIL, 숨겨도 되는 것은 `joints` 하나. 관절 점은 SPEC 4절의 색·3x3 그대로, 팔다리를 옮기면 점도 같이 옮긴다.
- **프레임 7개, 아래 표 순서대로 Aseprite 프레임 하나씩, 프레임 시간 = 표의 ms 그대로**(엔진이 이 ms 로 튼다. 바꾸고 싶으면 NOTES 에 제안만).
- 태그: `attack` 하나가 1~7 전체를 덮는다. 프레임별 태그를 더 달려면 표의 이름(`in`, `hold`, …) 그대로만.
- **세계 좌표**: 모든 프레임이 같은 바닥을 쓰고 **축발(뒷발 = `leg_near`)은 7프레임 내내 같은 자리(±3px), 바닥에 붙어 있다**. 걷기·달리기와 달리 엉덩이를 x=192 에 묶지 않는다 — 엉덩이가 앞뒤로 움직인다.
  그림 전체는 x=32~351 안(가장자리에 닿으면 FAIL, 띠 밖 32px 띠에 들어가면 경고). 몸의 전진(칸 전체를 앞으로 미는 것)은 엔진이 하므로 그리지 않는다.
- 무기 소품: 캐릭터 그림이 아니라 **납작한 단색 모양**(외곽선 1~2px 는 있어도 됨, 반투명 금지)으로, 닿는 거리·각도를 잴 수 있게만:
  - 칼(`weapon_front`, 가까운 손): 날 0.75 머리(83px) + 코등이 0.30 x 0.06 + 손잡이·폼멜 0.22 머리(24px) — 손 점에서 칼끝까지 0.85 머리(94px), 날 폭 0.08 머리(9px). 회색 계열(예 #C8C8D0, 손잡이 #8A5A2B).
  - 둥근 방패(`shield`, 먼 팔): 타원 0.68 x 0.90 머리(75 x 99px, posekit 방패 크기), 먼 손 점이 방패 안쪽 가운데. 예 #6E7F99.
  - 소품 색은 #FF00FF 와 RGB 거리 170 이상. 관절 점 색은 `joints` 레이어에만 쓴다.

## 관절 목표 (머리 단위 → 원본 px, 머리 110)
- 가로: **x px = 152 + 110·x** (152 = 이 세트의 대기 엉덩이 열; 이렇게 두면 7프레임 전체가 x=35~336 에 들어간다). 세로: **y px = 870 − 110·h** (h = 바닥 위 높이, 머리 단위).
- 손은 바닥 위 **실제 높이**로 적었다(`motion_chars.json` 의 손 값은 어깨선 기준 at() 단위 — 바꾼 값이다. 바닥 위 높이 = 엉덩이 높이 + (at 값 − 1.35)).
- 발목: 뒤(가까운 발) −0.90, 앞(먼 발) +0.80 머리 — **두 발 모두 7프레임 내내 그 자리**(축발은 뒷발). 발목 높이 0.12 머리(바닥에 평평).
- 칼 각도: 수학 각도(0° = 앞, 90° = 위, 180° = 뒤, 270° = 아래), 가까운 손 점에서 칼끝 방향. 각도는 **한 방향으로만** 돈다: 225 → 250 → 345 → 375(=15) — 뒤 → 아래 → 앞 → 앞-위로 올려 베기.

기울기 = 엉덩이 → 목 선의 앞 기울기(라디안, 괄호는 도). 머리는 몸통과 함께 돌린다(몸통 대비 머리 끄덕임 8° 이하, 목 점 대비 미끄럼 4px 이하 — 넘으면 경고).
클라우드가 이 표를 posekit 몸에 메모리에서만 세워 재 본 값(그림은 만들지 않았다): 팔다리 모두 닿음(IK 빠짐 0), 머리 x(두 발목 가운데 기준) hold −15px → contact +100px(이동 115px),
엉덩이 이동 63px, 휘두름 중간 → 맞는 순간 실루엣 변화 46%, 맞는 순간 → 지나침 27%, 지나침 → 돌아옴에서 대기 쪽으로 돌아감(관절 평균 거리 61 → 55 → 26 → 13px).
**이 표는 출발점이다** — 재생해 보며 고쳐도 된다. 다만 아래 「검사가 FAIL 로 잡는 것」은 지켜야 하고, 바꾼 값은 NOTES 에 px 로 적는다.

## 이 캐릭터만의 것 (브리긴다와 다른 점)
- **두 박자**: 방패는 휘두름 중간에 얼굴 높이로 가장 멀리 나가고(먼 손 x +0.95), 칼은 맞는 순간에 방패 **아래로** 지나간다. 브리긴다는 방패 자체가 맞는 순간이다.
- 칼: 준비에서 엉덩이 옆 **뒤-아래**(225°), 아래를 돌아 앞으로 올려 벤다. 브리긴다의 철퇴는 머리 높이 뒤에 겨눈 채 거의 돌지 않는다.
- 방패: 둥근 방패(0.68 x 0.90), 몸 앞 가슴~얼굴 높이. 브리긴다는 바닥 위 1.5 머리까지 내려오는 탑 방패.
- 발: 어깨너비보다 조금 좁게(−0.90 / +0.80), 두 발 모두 고정 — 브리긴다는 맞는 순간 앞발을 +0.15 머리 내딛는다.
- 준비: 엉덩이 1.28(덜 웅크림), 기울기 거의 0(꼿꼿이 방패 뒤). 브리긴다는 1.22 로 더 낮다.
- 클라우드 어림(같은 몸에 두 표를 세워 게임 크기 실루엣 IoU): hold 0.76, contact 0.71 — 기준 0.8 이하. 0.8 을 넘으면 FAIL 이니, 고칠 때 둘이 가까워지지 않게 한다.

## `motion_chars.json` 덮어쓰기와 다른 곳 (클라우드가 고친 이유 — 클라우드가 JSON 에 되돌려 넣는다)
- 발목 −1.10 / +1.00(posekit 대기 폭) → **−0.90 / +0.80**: 맞는 순간 엉덩이(+0.27, 1.20)에서 뒷발목 −1.10 까지는 다리 길이(1.63 머리)보다 멀어 닿지 않는다.
- hold 기울기 0.12 → **0.04**, contact 0.22 → **0.32**, 엉덩이 (−0.22, 1.30) → **(−0.30, 1.28)**: 검사는 준비에서 머리가 두 발목 가운데보다 **뒤**, 맞는 순간 **앞**, 그 사이 100px 이상 이동을 요구한다. 원래 값 그대로면 hold 의 머리가 발 가운데 앞 +2px, 이동 76px 로 FAIL(SPEC 10.4 의 시험).
- hold 칼 각도 190° → **225°**, 맞는 순간 손 x 1.15 → **0.85**, 칼 1.35 머리(posekit) → **0.85 머리**: 원래 값으로는 7프레임을 합친 폭이 384px 칸을 넘는다(칼끝이 뒤로 −1.41, 앞으로 +2.07 머리).
- 방패 값은 at() 단위를 바닥 위 높이로 바꿔 적었다(같은 자리).

## 시작하는 법 (PC 가 고른다)
1. **스크립트(권장)**: 걷기 때 `walk8_pc.py` 처럼 `tools/pixelart/posekit.py` 몸(`pk.Body(4.0)`, `pk.build(pose, B, 'none')`)과 `tools/pixelart/walk8.py` 의 그리기·레이어 나누기(`draw`, `frame_layers`, `floor_row`)를 불러,
   위 표를 포즈로 넣고 부위 레이어 PNG + `joints` 점을 프레임마다 쓴다. 포즈 키: `hip=(x, h)`, `lean`, `tilt`, `footN=(−0.90, 0.12)`, `footF=(0.80, 0.12)`, `handN=('p', x, h)`, `handF=('p', x, h)`, `elbN`/`elbF`(팔꿈치 굽는 쪽), `faN=faF=0`.
   `frame_layers` 는 엉덩이 0 을 x=192 에 둔다 — 이 세트는 x=152 가 0 이므로 모든 x 에서 (192−152)/110 = 0.36 을 빼고 그리면 된다. 칼·방패 소품은 스크립트에서 위 크기대로 그린다.
   실행: `uv run --no-project --with pillow --with numpy python ~/Documents/pm-pc-scratch/mannequin_pc.py . ~/Documents/pm-pc-scratch/atk__class_warrior` (이 저장소 폴더에서, 스크립트는 스크래치 폴더에).
   레이어 PNG 로 `.aseprite` 를 조립하는 것은 걷기 v2 때와 같은 방법(aseprite-mcp 도구)으로. 프레임 시간·`attack` 태그·`joints` 숨김을 표대로.
2. **몸 틀**: `art/requests/guides/walk_base/v2/walk_base.aseprite` 나 `art/requests/guides/run_base/v1/run_base.aseprite` 를 스크래치에 복사해 부위 레이어(팔·다리·몸통·머리, 같은 뼈 길이·관절 점)를 옮겨 자세를 만든다. 뼈 길이는 바꾸지 않는다(넓적다리·정강이 89.65px, 위팔 68.2, 아래팔+손 71.5, ±2px 넘으면 FAIL).
3. 어느 쪽이든 Aseprite 에서 **재생해 본다**(ms 그대로, 양파 껍질). 클라우드는 정지 수치만 맞췄다 — 맞는 순간이 "딱" 하고 읽히는지는 PC 만 볼 수 있다.
