중량은 판금·큰 방패·아주 큰 무기를 든 몸이다. 여전히 **그 몸이 낼 수 있는 가장 빠른 이동**(주인: 전투 이동은 달리기)이지 산책이 아니다 —
그러나 **뜨는 프레임이 없고**(늘 한 발은 땅), **상체는 서 있고**(기울기 **5°**, 4~6), **몸이 땅에서 솟지 않고**, **디딜 때마다 무게가 떨어진다.**

## 느낌 (말로)
갑옷을 입고 방패와 무기를 든 채 **서둘러 밀고 나가는** 병사 — 무릎을 늘 굽히고 짧고 빠르게 **쿵, 쿵, 쿵** 내딛는다(1분에 149걸음). 느긋한 산책이 아니다.
- 디디는 발은 발바닥 전체로 **평평하게 내려찍는다**. 무게는 **내려앉음(H2·H6) 한 칸에서만 툭 떨어진다**(엉덩이 7px) — 그다음 지나감·밀어냄에서 천천히 돌아오지만
  **닿음 높이를 넘지 않는다**(밀어냄은 닿음보다 0.5px 낮다). 몸이 위로 솟는 칸이 없다.
- 지나가는 발은 **낮게** 끌듯이 지나간다(발바닥 5~13px, 걷기 30~36px). 무릎은 늘 굽어 있다(지나감 49~51°) — 곧게 서서 넘어가면 걷기로 읽힌다.
- **팔은 몸에 붙이고 높게** 든다: 먼 팔(방패)은 팔꿈치를 옆구리에 붙이고 아래팔을 가슴 앞으로 가로지르게(손 높이 215~237px, 가슴), 가까운 팔(무기)은 손을 허리띠 높이
  (177~200px)에 두고 아래팔을 앞으로. 걸음 따라 **몇 도만** 흔들린다(손의 앞뒤 이동 가까운 손 18px · 먼 손 7px — 경량 달리기 v2 는 107~111px). 팔꿈치는 내려앉음에서 조금 더 접힌다(손이 무게와 같이 가라앉는다).
- 상체는 **5°** 로 거의 서 있고 칸마다 같다(변화 0.8°). 머리는 수평.

## 시간 — 게임이 실제로 잡는 칸 시간
게임(`js/battle.js` `runCells`)은 중량·로브의 그려진 이동 칸을 **디딘 채로** 넘긴다: 한 칸 = 몸이 그려진 보폭의 1/4(ds/4) 를 가는 동안. 유닛의 빠르기는 그대로다
(주인 결정: 발 미끄럼은 "그대로 둠 (B만)" — 빠르기는 두고 박자만 고친다). 1배속 유닛 빠르기 약 58 게임 px/초 이면
**한 칸 = (23.5 / 4) / 58 = 101ms**(8칸 808ms, 1분에 149걸음). 이 초안의 프레임 시간이 101ms 인 까닭이고, **느낌은 이 101ms 에서 본다.**
느린 유닛·1.5배 우두머리 시트는 칸마다 같은 비율로 길어진다(예: 빠르기 50 이면 118ms). 같은 빠르기의 경량 달리기는 닿음·내려앉음 196ms, 밀어냄·뜸 98ms(보폭 45.5px).

## PC(Aseprite)가 할 일
1. 초안을 납품 폴더로 복사한다: `draft/heavy_base.aseprite` → `../pixel-management-inbox/art/inbox/guides/heavy_base/heavy_base.aseprite`.
   Aseprite 로 열어 **101ms 로 재생**하고 `draft/heavy_base_vs_run.gif` 와 견준다. 클라우드는 정지 그림·숫자로만 맞췄다 — 재생해서
   **"갑옷 입은 몸이 서둘러 밀고 나간다"** 로 읽히는지(경량처럼 뜨거나 숙이지 않고, 산책처럼 느긋하지 않게) PC 만 볼 수 있다.
2. 클라우드가 본 다듬을 곳(초안의 솔직한 약점):
   - **방패 팔**: 맨손 마네킹이라 먼 팔의 아래팔이 가슴 앞으로 곧게 뻗은 막대로 보인다. 방패를 얹으면 가려지는 자리다 — 손 높이(가슴)와 작은 흔들림은 지키고 모양만 다듬는다.
   - **H2·H6(내려앉음)** 뒷발이 뒤로 들린 모양(발끝 아래 34°): 무거운 장화라면 더 끌리듯 낮아도 좋다(바닥 위 3px 이상).
   - **"쿵" 의 자리**: 무게는 H2 한 칸에서 7px 떨어진다. 재생해서 쿵이 H2 에 읽히는지 본다. 오르내림을 키우려면 **내려앉음을 더 낮게**(밀어냄을 높이지 않는다 — 몸이 솟으면 경량이다).
3. SPEC 3절(캔버스)·4절(레이어)을 지킨다. 뼈 길이는 바꾸지 않는다. **팔다리를 옮기면 `joints` 레이어의 그 관절 점도 같이 옮긴다**(점 색·크기 SPEC 4절, `joints` 는 숨긴 채 저장).
   레이어 이름·순서·384x1024·8프레임·101ms 는 그대로. 엉덩이 중심(두 엉덩이 점의 가운데)은 모든 프레임에서 x=192 (±1). 아래 「검사 기준」의 실패 항목을 지킨다.
4. 자체 검사 (이 저장소 폴더에서):
   `python3 tools/art/check_skeleton.py ../pixel-management-inbox/art/inbox/guides/heavy_base/heavy_base.aseprite --gait heavy --pose art/requests/guides/heavy_base/draft/pose.json`

5. 납품: art-inbox `art/inbox/guides/heavy_base/heavy_base.aseprite` **하나**(띠·GIF 는 클라우드가 뽑는다). `art/inbox/` 밖은 건드리지 않는다.

## 엔진·등록
- 중량 캐릭터의 이동 프레임은 **`anims.run`** 으로 붙인다(전투 이동 = 달리기 칸; 세 부류 모두 같은 자리). `add_gait.py <시트> --gait run --src … --pose art/requests/guides/heavy_base/draft/pose.json`
  → `runStride` 23.5, 시트에 `gait: heavy` 를 적는다. 엔진은 이 칸을 디딘 채로(칸마다 ds/4) 넘긴다 — 위 「시간」.
- 어느 캐릭터가 중량인지는 이 README 가 정하지 않는다 — **부류 표는 `tools/art/specs/gait_classes.json`**(엔진 표 `js/gait_classes.js` 는 `python3 tools/art/gait_requests.py --js` 로 만든다).
  그 표의 `classes.heavy` 가 이 세트와 같은 수치(기울기 5°, 보폭 23.5, 101ms)를 적는다.
