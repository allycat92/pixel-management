# 중량 이동 뼈대 (8프레임) · `guide/heavy_base` — 공통 규칙은 `art/requests/guides/SPEC.md` (달리기 5b절과 걷기 5절의 캔버스·레이어·관절 점)

**상태 (2026-11-26): DRAFT — 클라우드 초안 `draft/` (`tools/pixelart/gait8.py --style heavy`). PC 다듬기 기다림.**
`check_skeleton.py` 에 이 세트의 모드(`heavy`)가 아직 없다 — 아래 「자체 검사」의 임시 명령과 기대 출력대로 본다.

**왜 만드나 (주인 2026-11-26)**: "달리기(이동)에 대해 3가지 부류를 정하고 싶어. 경량, 중량, 로브. … 중장비를 갖추면 당연히 뛰는건 물론이고
몸이 저렇게 땅에서 떨어지거나 몸을 앞으로 기울인 채로 가누기도 어려울테니까."
→ 전투 이동은 세 부류다: **경량** = 받아들인 달리기(`../run_base/v2/`), **중량** = 이 세트, **로브** = `../robe_base/`.
중량은 판금·큰 방패를 든 몸이다. 여전히 **그 몸이 낼 수 있는 가장 빠른 이동**(주인: 전투 이동은 달리기)이지 산책이 아니다 —
그러나 **뜨는 프레임이 없고**(늘 한 발은 땅), **상체는 거의 서 있고**(8~10°), **발을 디딜 때마다 엉덩이가 무게로 가라앉는다.**
**누가**: 마네킹 시퀀스는 PC(Aseprite)가 만든다(주인 "마네킹 시퀀스도 pc하청으로"). 아래 초안은 클라우드가 수치표로 구운 **출발점**이다.

## 느낌 (말로)
무거운 갑옷을 입고 서두르는 병사 — 무릎을 늘 굽힌 채 짧고 빠르게 **쿵, 쿵** 내딛는 달리기(땅을 떠나지 않는 달리기).
- 디디는 발은 발바닥 전체로 **평평하게 내려찍는다**(뒤꿈치부터 굴러 들어가지 않는다). 디딘 다음 프레임(내려앉음)에 엉덩이가 10px 가라앉는다 — 무게.
- 지나가는 다리는 **낮게** 지나간다(발바닥 16~18px, 걷기 30~36px). 무릎을 높이 들지 않는다.
- 지나감에서도 디딘 무릎이 44° 굽어 있다 — 걷기처럼 곧게 서서 넘어가면(무릎 15° 이하) 걷기로 읽힌다. 이것이 걷기와의 차이다.
- 팔은 몸에 붙인다(방패·무기를 들고 있다): 위팔 흔들기 ±13° 정도, 손은 허리띠 높이. 손은 엉덩이보다 **한 프레임 늦게** 내려간다(팔꿈치가 내려앉음에서 더 접혔다가 지나감에서 펴진다).
- 머리는 수평을 지킨다(쪼지 않음).

## 수치 (초안 `draft/` — 원본 px, 머리 110 기준 → 게임 px 는 x0.1654)
- **한 걸음 = 몸이 한 걸음에 가는 거리 133px → 게임 22.0px (`runStride`).** 경량 275px(45.5) 의 절반 남짓. 몸은 프레임마다 33.3px 간다.
  디딘 발의 **발끝**(발바닥 앞 끝, 바닥 줄 위 4줄 안)은 그 발이 땅에 있는 다섯 프레임(H1 닿음 → H2 → H3 → H4 → H5 의 뒷발)에서 프레임마다 정확히 33.3px(±3) 씩 물러난다.
  초안 발끝 x(엉덩이 기준): 가까운 발 86 → 53 → 19 → -13 → -46, 먼 발 91 → 58 → 24 → -9 → -43 (물러남 32~34px).
  (걷기 검사기의 "닿을 때 발목~발목"으로 재면 127px 다 — 뒷발이 발끝으로 굴러 발목이 6px 앞에 있어서다. 한 걸음은 발끝으로 잰다)
- 엉덩이 높이(검사기가 재는 엉덩이 중심): 닿음 184 · **내려앉음 174** · 지나감 182 · 밀어냄 188px → **오르내림 14px(게임 2.3px)**,
  가라앉음 = 밀어냄 → 닿음 -4 → 내려앉음 -10px. 가장 낮은 곳은 내려앉음(H2·H6). (수치표의 엉덩이 관절 높이는 179 / 169 / 178 / 184px — 걷기·달리기와 같이 점이 약 4px 높게 잰다)
- 상체 기울기(엉덩이 → 목 점): 8.5° · **9.6°** · 8.5° · 7.9° (수치표 0.10~0.13rad). 달리기 19~31°, 걷기 8~11° — 기울기로는 걷기와 같다. 목 점 이동 3.4px.
- 무릎: 닿음 24° / 34°(앞발 / 뒷발), 내려앉음 56° / 59°, 지나감 44° / 45°(디딘 다리), 밀어냄 33° / 33°.
- 들린 발 바닥 높이: 내려앉음 10~14px, 지나감 16~18px, 밀어냄 8px(내려올 발). 걷기 30~36px · 달리기 56px 이상과 다르게 **낮게**.
- 팔(위팔 각도는 아래로 곧게 = 0°, 앞 +; 팔꿈치 굽힘): 디딘 쪽 팔 -10/50 → -13/56 → -4/46 → +6/48, 반대쪽 +10/50 → +13/56 → +4/46 → -6/48.
  먼 팔은 어깨가 그림에서 0.7머리 앞이라 10° 더 뒤로 친다(FAR -16/56 … +3/62). 팔꿈치 46~62°, 손은 허리띠 높이. 손의 앞뒤 이동(어깨 기준) 가까운 손 33~82px, 먼 손 27~68px.
- 시간: **한 프레임 110ms**(8프레임 880ms, 1분에 136걸음). 이 속도에서 발이 붙어 있으려면 몸이 초당 50px(게임) 가야 한다.
  게임은 그려진 칸을 **간 거리로** 넘긴다(SPEC 9절) — 실제 프레임 시간은 유닛의 빠르기로 정해진다(전사 1배속: 보폭 약 20.5px, 초당 약 3걸음 → 한 칸 약 83ms).
  그려진 보폭 22.0px 이 코드 보폭(약 20.5px)과 거의 같아 **디딘 발 미끄럼은 칸마다 약 0.4px**(경량 run_base 는 약 6px) — 발이 바닥에 붙는다.
- 그림은 x=32~351 안(초안 최대 x 는 바닥 줄 근처 발끝과 앞 손 — 모두 안), 뒷발 발끝 그림 안, posekit 경고 0.

## PC(Aseprite)가 할 일
1. 초안을 납품 폴더로 복사한다: `draft/heavy_base.aseprite` → `../pixel-management-inbox/art/inbox/guides/heavy_base/heavy_base.aseprite`.
   Aseprite 로 열어 **110ms 로 재생**하고 `draft/heavy_base_vs_run.gif` 와 견준다. 클라우드는 정지 그림·숫자로만 맞췄다 — 재생해서
   **"무거운 몸이 서둘러 달린다"** 로 읽히는지(경량처럼 뜨지 않고, 걷기처럼 느긋하지 않게) PC 만 볼 수 있다.
2. 클라우드가 본 다듬을 곳(초안의 솔직한 약점):
   - **H3·H7(지나감) 무릎 44°**: 숫자로는 "곧은 다리 = 걷기"를 피하려는 값인데, 정지 그림에서 조금 쪼그린 것처럼도 보인다. 재생해서 쪼그린 느낌이면 35° 까지 펴도 된다(그 아래는 걷기).
   - **H2·H6(내려앉음)** 뒷발이 뒤로 차올라 있다(발목 높이 0.40머리, 발끝 아래 42°) — 무거운 장화라면 더 끌리듯 낮아도 좋다(바닥 위 6px 이상은 지킨다).
   - **팔**: 초안은 맨손 마네킹이라 손이 허리띠 앞에서 작게 흔들린다. 방패·무기를 들었을 때 이 정도로 몸에 붙어 있는지 본다 — 직업별 무기 드는 방식은 SPEC 7절 표를 이 위에 얹는다.
   - **가라앉음의 박자**: 엉덩이는 H4 → H1 → H2 에서 4px, 10px 내려간다. "쿵" 이 H1(닿음) 에 읽히는지 H2 에 읽히는지 재생해서 정한다. 무게는 꼭 보여야 한다(가라앉음 합 12px 이상 = 게임 2px).
3. SPEC 3절(캔버스)·4절(레이어)을 지킨다. 뼈 길이는 바꾸지 않는다. **팔다리를 옮기면 `joints` 레이어의 그 관절 점도 같이 옮긴다**(점 색·크기 SPEC 4절, `joints` 는 숨긴 채 저장).
   레이어 이름·순서·384x1024·8프레임·110ms 는 그대로. 엉덩이 중심(두 엉덩이 점의 가운데)은 모든 프레임에서 x=192 (±1).
   지켜야 하는 것(아래 「검사기에 넣을 기준」의 실패 항목):
   - **어느 프레임이든 한 발은 y=870 에 있다**(뜨는 프레임 없음). H1·H5 는 **두 발 모두** y=870. H2~H4·H6~H8 의 다른 발은 바닥 위 6px 이상.
   - 디딘 발 **발끝**은 다섯 프레임(닿음 → … → 다음 닿음의 뒷발) 동안 프레임마다 같은 거리(33px, ±3)씩 물러난다. 한 걸음 133px ±10 — 바꾸려면 먼저 묻는다.
   - 상체는 서 있다(기울기 5~12°). 달리기처럼 숙이지 않는다 — 주인 결정의 핵심.
4. 자체 검사 (이 저장소 폴더에서). **지금 `check_skeleton.py` 에는 `heavy` 모드가 없다**(`--pose draft/pose.json` 만 주면 `unknown gait "heavy"` 로 FAIL).
   그때까지는 걷기 규칙으로 공통 항목(캔버스·레이어·관절 점·뼈 길이·엉덩이 x=192·머리)만 확인한다:
   `uv run --no-project --with pillow --with numpy python tools/art/check_skeleton.py ../pixel-management-inbox/art/inbox/guides/heavy_base/heavy_base.aseprite --gait walk --base art/requests/guides/heavy_base/draft/heavy_base.aseprite`
   초안을 그대로 재면 다음 줄들만 나온다 — **이 줄들은 중량 이동에서 의도한 것이니 무시**하고, 그 밖의 `FAIL`/`WARN` 이 있으면 고친다:
   `FAIL: W1/W5: step 127.0 px, must be 135-151` · `WARN: frame duration differs … 120 ms` (110ms 가 맞다) · `WARN: W3/W7 (passing): the supporting knee is bent 44 deg …` ·
   `WARN: W3/W7 (passing): the lifted foot is 16/18 px …` · `WARN: W3/W7 (passing): the lifted knee leads … 37/25 px` · `WARN: W6: the forward hand is -13 px outside the torso`.
   걷기 모드의 `planted near ankle x` 줄은 발목이다 — 발끝 물러남은 아직 손으로 본다(Aseprite 에서 바닥 줄 위 4줄의 발 앞 끝 x).
   `heavy` 모드가 생기면 `--gait walk` 를 빼고 `--pose art/requests/guides/heavy_base/draft/pose.json` 을 붙인다(그때 이 README 를 고친다).
5. 납품: art-inbox `art/inbox/guides/heavy_base/heavy_base.aseprite` **하나**(띠·GIF 는 클라우드가 뽑는다). `art/inbox/` 밖은 건드리지 않는다.
   NOTES 절 「뼈대 — 중량 이동 (Aseprite)」: 바꾼 프레임과 수치(px), 검사 줄(위의 의도된 줄 포함), 재생해 본 느낌. 커밋 `Touch up guide heavy_base (Aseprite)`.
   손댈 곳이 없으면 그렇게 적고 초안을 그대로 올려도 된다.

## 검사기에 넣을 기준 (도구 담당 — `check_skeleton.py --gait heavy`, `pose.json` 의 `"gait": "heavy"`; PC 는 읽기만)
`run` 모드처럼 공통 항목(캔버스·레이어·관절 점·뼈 길이 ±2·딱 떨어지는 가장자리·엉덩이 x=192 ±1·머리 레이어·머리 쪼임 4px·머리 기울기 8°)은 그대로, 걸음 항목만 바꾼다. 프레임 이름 H1~H8.
- **실패**: 어느 프레임이든 두 발이 모두 y=870 에서 떨어짐(뜸 금지) · y=870 아래 픽셀 · H1·H5 에서 두 발 중 하나라도 y=870 이 아님(두 발 디딤) ·
  H2~H4·H6~H8 에서 디딘 발이 y=870 이 아님 / 다른 발이 바닥 위 6px 미만 · 디딘 발끝(그 다리 레이어의 y=866~870 앞 끝 x)이 닿음 → 내려앉음 → 지나감 → 밀어냄 → 다음 닿음(뒷발)에서
  프레임마다 step/4 ±3px 씩 물러나지 않음(step = 발끝 H1 − 발끝 H5 뒷발, 네 번의 물러남) · step 이 `pose.json` `step_px`(133) ±10px 밖 ·
  H(i+4) 가 H(i) 의 좌우 바꿈이 아님(엉덩이 ±1, 발목 x ±2, 발목 높이 ±4).
- **경고** (초안 값): 기울기 5~12° 밖(7.9~9.6) · 기울기 변화 4° 초과(1.7) · 목 점 이동 12px 초과(3.4) · 오르내림 10~20px 밖(14) ·
  내려앉음(H2·H6)의 엉덩이가 그 반쪽에서 가장 낮지 않음(±2) · 가라앉음(밀어냄 → 내려앉음 엉덩이 차) 12px 미만(14 — 무게가 안 보인다) ·
  지나감의 디딘 무릎 30~55° 밖(44 / 45 — 30° 미만은 걷기, 55° 초과는 쪼그림) · 내려앉음 무릎 45~70° 밖(56 / 59) · 닿음의 앞발목 엉덩이 앞 30~70px 밖(50) ·
  들린 발 바닥 30px 초과(최대 18 — 무거운 발은 낮게) · 팔꿈치 35~80° 밖(46~62) · 한 손의 앞뒤 이동(어깨 기준 최대 − 최소) 60px 초과(가까운 손 49, 먼 손 41 — 팔을 크게 치면 경량이다) ·
  프레임 시간 ≠ `nominal_ms` 110 · 이웃 프레임 실루엣 차이 8% 미만(초안 21~30%).
- 띠 검사: `check_delivery.py` 를 `--flight-slots` **없이**(모든 칸의 맨 아래 픽셀이 y=870 — 뜬 프레임이 없다). `receive.py` 는 `pose.json` 의 gait 가 `run` 이 아니면 이미 그렇게 한다.
- `receive.py guides/heavy_base` 는 `draft/` 의 `pose.json` 을 `--pose` 로 넘긴다 — `heavy` 모드가 생기기 전에는 `unknown gait` 로 FAIL 한다(예상된 것).
