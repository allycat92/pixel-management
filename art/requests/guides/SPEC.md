# 뼈대(자세 가이드) 제작 지침 — 모든 뼈대 세트 공통

뼈대 = 그림 쪽(GPT)이 캐릭터 프레임을 그릴 때 따라 그리는 4등신 마네킹 자세. 게임에 들어가는 그림이 아니다.
2026-11-25 걷기 시범(`walk_base` 4프레임)을 검토한 결과를 반영해 정한 규칙이다. 개별 세트의 README 보다 이 문서가 우선한다.

**주인 결정 (2026-11-26): 전투에서 유닛은 달린다.** "걷기만 남기는건 동의하지 않아. 기본적으로 전투잖아? 차라리 뛰기 모션만 있는게 맞지
걷기만 하는건 어색하지 않을까." → 전투 이동의 기본 동작은 **달리기(5b절, `run_base` / `run_<class>`)** 다. 걷기 세트(5절, `walk_base`)는
지우지 않는다 — 참고 자료이자 느려진 유닛(거미줄 등 둔화)용으로만 남긴다. 직업별로 새로 그릴 이동 프레임은 달리기부터다.

## 1. 누가 무엇을 하나

| 만들기·다듬기 | PC(Aseprite) | **마네킹(뼈대) 시퀀스는 PC 가 만든다** (주인 2026-11-26: "마네킹 시퀀스도 pc하청으로"). 사양대로 **레이어가 나뉜 8프레임 `<set>.aseprite`** 를 만들고 **재생해 보며** 손으로 다듬는다(양파 껍질 보기). 팔다리를 옮기면 `joints` 레이어의 그 관절 점도 같이 옮긴다. 바꾼 곳을 px 로 NOTES 에 적는다 ("W3 든 발목 x +8"). 납품은 `.aseprite` 하나면 된다 |
| 출발점 | 클라우드(이미 만든 것) | 클라우드가 자세 수치표로 구운 초안 — 걷기 `walk_base` v2 (`tools/pixelart/walk8.py --aseprite`), 달리기 `run_base` v1 (`tools/pixelart/run8.py --aseprite`). PC 는 이것을 복사해 출발점으로 써도 된다. 수치가 저장소에 남아 다시 만들 수 있다 |

| 교차 검수 | GPT | 사람 눈으로만 판단할 수 있는 것 3문항 이내 (걷기로 읽히나 · 이 위에 옷을 그릴 수 있나 · 무게감) |

## 2. 세트 이름과 파일
- 요청: `art/requests/guides/<set>/README.md` · 납품: art-inbox `art/inbox/guides/<set>/`
- `<set>` = `run_base`, `run_<class>` (전투 이동의 기본), `walk_base`, `walk_<class>` (참고·둔화용)
  (class = warrior | archer | mage | cleric | rogue), 대장 전용은 `run_<captain key>` / `walk_<captain key>`
- 공격·피격·대기 마네킹 시퀀스는 캐릭터마다: `<동작>__<시트 stem 에서 sheet_ 를 뺀 것>`, 동작 = `atk` | `hit` | `idle`
  (예: `atk__class_warrior`, `atk__captain_ironwall`, `hit__captain_shadowqueen`, `idle__class_warrior`). 파일·좌표·검사는 10절 — 아래 두 줄(8프레임, 엉덩이 x=192 고정)은 걷기·달리기 이야기다
- 작업 파일(납품의 본체): `<set>.aseprite` — **한 프레임 384x1024, 8프레임 x 120ms (달리기는 8프레임 x 80ms)**, 4절의 레이어. 엉덩이 중심이 x=192 에 고정(몸은 제자리, 발이 움직인다)
- 클라우드가 거기서 뽑는 것: `<set>_a.png` (1~4번 프레임을 나란히), `<set>_b.png` (5~8번), `<set>_preview.gif`(게임 크기 0.1654배 → 4배 확대), `pose_measured.json`.
  띠는 프레임 네 장을 그대로 이어 붙인 것이다(프레임의 x=192 가 띠 칸의 가운데)

## 3. 캔버스 (기존 `guide_strip.png` 와 같은 규격)
- 띠 1536x1024 RGB(= 384x1024 프레임 4장), 배경 완전한 #FF00FF, 한 줄 4자세(1x4), 오른쪽을 보는 정면 3/4, 머리 110px(4등신, 귀·외곽선 포함 약 117px)
- **바닥은 모든 프레임에서 같은 줄**: 디딘 다리의 맨 아래 픽셀이 y=870 (닿음 프레임은 두 다리 모두). 프레임마다 그림을 위아래로 밀어 맞추지 않는다 — 발목 높이를 고친다.
  달리기는 한 번에 한 발만 디디고, 뜬 프레임(R4·R8)은 아무것도 y=870 에 닿지 않는다(5b절) — 그래도 바닥 줄은 같은 y=870 이다
- 자세 사이·테두리 마젠타 32px 이상, 가장자리는 딱 떨어지게(배경과 섞인 색·반투명 없음)
- 색·외곽선은 posekit 마네킹 그대로: 가까운(오른) 팔다리 밝게, 먼(왼) 팔다리 어둡게
- **배율은 모든 프레임·모든 직업에서 하나.** 네 자세가 안 들어가면 무기 드는 방식을 바꾸지 배율을 줄이지 않는다
- **보이는 크기 규칙**: 게임은 약 1/6 로 줄인다. 원본에서 6px 미만의 차이는 게임에서 안 보인다(1px 미만). 동작의 핵심 변화는 원본 12px 이상으로 잡는다

## 4. `.aseprite` 레이어 (아래 → 위)
Background(#FF00FF) · cloth_back(망토) · weapon_back · arm_far · shield · leg_far · leg_near · torso · cloth_front(치마·로브 자락) · head · weapon_front · arm_near · joints(숨김)
- 없는 부위의 레이어는 생략(몸 6개 + joints 는 필수). 숨겨도 되는 레이어는 `joints` 하나뿐
- **`joints` = 관절마다 3x3 점 하나, 색으로 구분** (가까운 쪽 / 먼 쪽): 엉덩이 관절 `#FFFF00` / `#C8C800` · 무릎 `#00FF00` / `#00AA00` · 발목 `#00FFFF` / `#00AAAA` ·
  어깨 `#FF8000` / `#C86400` · 팔꿈치 `#FF0000` / `#AA0000` · 손끝 `#0000FF` / `#0000AA` · 목 `#FFFFFF`. 클라우드는 이 점으로 뼈 길이·걸음·오르내림을 잰다.
  팔다리를 옮기면 그 점도 같은 만큼 옮긴다(점이 제 부위 레이어 위에 없으면 검사 실패). 점의 색·크기는 바꾸지 않는다
- `docs/pc_cloud_protocol.md` 의 "가이드 레이어는 커밋 전에 지운다"는 캐릭터 시트 규칙이다. 뼈대 세트에는 적용하지 않는다

## 5. 걷기: 8프레임
4프레임(닿음·지나감만)은 무게를 싣는 순간과 밀어내는 순간이 없어 발을 끄는 것처럼 보였다. 게임은 걸은 거리에 맞춰 프레임을 넘기므로
4프레임이면 한 프레임이 0.14~0.22초 떠 있고 디딘 발이 장화 길이만큼 미끄러진다. 8프레임이면 절반이다(주인이 준 참고도 8프레임 x 120ms).

| 프레임 | 이름 | 내용 |
|---|---|---|
| W1 | 닿음 (가까운 발) | 앞발 **뒤꿈치**가 닿는다(발끝 15~25° 들림), 뒷발은 **발끝**으로 민다(뒤꿈치 30~40° 들림). 두 발 모두 땅 |
| W2 | 내려앉음 | 앞발 바닥 전체, 앞무릎이 굽으며 무게를 받는다(엉덩이 가장 낮음). 뒷발은 막 떨어져 뒤로 차올림. **팔 흔들기의 끝**(닿음보다 한 프레임 늦게) |
| W3 | 지나감 | 디딘 다리가 **곧게**(무릎 굽힘 15° 이하) 엉덩이 아래에. 든 다리는 무릎이 앞서 나간다(무릎이 디딘 무릎보다 38px 이상 앞) |
| W4 | 올라섬 | 디딘 발 뒤꿈치가 들리기 시작(엉덩이 가장 높음), 든 발이 발끝을 들고 앞으로 뻗는다 |
| W5~W8 | 반대쪽 | 같은 것을 먼 발로. W(i+4) 는 W(i) 의 좌우 바꿈: 엉덩이 높이 ±1px, 발 x ±2px |

수치 (원본 px, 머리 110 기준 → 게임 px)
- **몸 오르내림은 다리 길이에서 나온다**: 엉덩이 관절 높이 닿음·내려앉음 177~181px, 지나감·올라섬 190px 이상 → 오르내림 12~16px(게임 2~2.7px).
  (점으로 잰 값은 장화 밑창 두께만큼 약 4px 크게 나온다 — 검사는 높이의 차이와 순서만 본다)
  (시범 README 의 "4~8px"은 곧은 디딘 다리와 양립하지 못해 무릎이 34° 굽은 엉거주춤이 됐다 — 폐기)
- 한 걸음(닿을 때 발목~발목) 143px ±8 (다리 길이의 0.74) → 23.7px. 디딘 발은 프레임마다 정확히 한 걸음의 1/4 씩 뒤로(±3px) — 발 미끄럼 기준.
  앞발은 엉덩이 앞 62px, 뒷발은 뒤 81px 에 둔다(앞으로 숙인 몸): 가까운 쪽 엉덩이 관절이 중심보다 뒤에 있어, 앞발을 더 멀리 두면 닿는 순간 다리가 바닥에 닿지 않는다
- 든 발 바닥 높이(지나감) 30~36px → 5~6px
- 팔: 앞으로 가는 팔 위팔 +30°·팔꿈치 35~45° 굽힘, 뒤로 가는 팔 -28°·팔꿈치 8~12°. 앞으로 간 손은 **두 팔 모두** 몸통 앞 가장자리 밖으로 20px 이상. 손의 앞뒤 이동 합 150px 이상
- 상체: 앞으로 기울기 내려앉음 0.15rad → 올라섬 0.10rad (머리 x 이동 8~10px, 12px 넘으면 쪼는 것처럼 보인다). 지나감 두 프레임(W3·W7)은 엉덩이 위가 서로 달라야 한다(팔 위치 반대)
- 기준 수치표: `tools/pixelart/walk8.py` (지금 초안: 한 걸음 143px, 오르내림 15.4px, posekit 경고 0, `check_skeleton.py` 경고 0)

## 5b. 달리기: 8프레임 — 전투 이동의 기본 (`run_base`, 주인 결정 2026-11-26)
걷기와 다른 점은 셋이다: **두 발이 모두 뜨는 프레임이 있다**, **한 번에 한 발만 디딘다**(두 발이 같이 땅에 있으면 걷기다), **상체가 훨씬 숙는다**.
**주인이 받아들인 달리기(4판, PC `a94de43` = `run_base/v2/`)**: "몸이 떠야 할 타이밍에 오히려 앞으로 숙이면서 눌리는 느낌을 원한다. 한번 치달리고 발을 디뎌 몸을 가누는 동작이 끝날 즈음에는 다시 몸을 살짝 일으키고",
그 앞 판에서 "살짝 앞으로 숙이고 위아래 움직임은 적게" — **치달림은 숙임으로 만든다**(뜸에서 가장 숙임), 디뎌 가눈 뒤 조금 일어선다, 엉덩이는 거의 평평(살짝 뜨는 느낌만, 깡충거림 없음).
마네킹·캔버스·바닥 줄·레이어·관절 점은 걷기와 완전히 같다(뼈 길이도).

| 프레임 | 이름 | 내용 |
|---|---|---|
| R1 | 닿음 (가까운 발) | 발이 **몸보다 앞**(발목이 엉덩이 앞 62px)에 발바닥 전체로 닿는다, 디딘 무릎은 조금 굽힘(v2 14° / 36°), 상체 24°. 반대 다리는 뒤에서 접혀 뒤꿈치가 올라가 있다 |
| R2 | 내려앉음 · 가눔 | 받아냄: 엉덩이가 가장 낮고(조금), 디딘 무릎 약 50°, 몸무게가 발 위에. **상체가 가장 일어선다(19°)** — 디뎌 몸을 가눈 끝. 반대 무릎이 몸 아래를 지나간다. 두 팔이 엇갈려 지나가는 순간 |
| R3 | 밀어냄 | 디딘 다리가 **몸 뒤로 뻗는다**(무릎 굽힘 30° 이하), 뒤꿈치가 들리고(12°) 발끝으로 민다. 상체가 다시 숙는다(29°), 반대 무릎이 앞으로 치고 나간다 |
| R4 | 뜸 | **두 발 모두 바닥에서 뚜렷이 떨어진다**(맨 아래 픽셀이 바닥 위 18px 이상), **상체가 가장 숙는다(31°)** — 앞으로 숙이며 눌림. 엉덩이가 가장 높을 필요는 없다. 다리는 가위(앞다리는 다음 디딤으로, 뒷다리는 뒤에) |
| R5~R8 | 반대쪽 | 같은 것을 먼 발로. R(i+4) 는 R(i) 의 좌우 바꿈: 엉덩이 높이 ±1px, 발목 x ±2px, 발목 높이 ±4px |

수치 (확정판 `run_base/v2/` = `tools/pixelart/run8.py` 의 지금 수치표에서 잰 값 — 원본 px, 머리 110 기준 → 게임 px 는 x0.1654. 괄호의 「v1」은 클라우드 첫 초안 `v1/`)
- **한 걸음 = 몸이 한 걸음에 가는 거리 = 한 발이 닿은 곳에서 다음 발이 닿는 곳까지 275px(2.5머리) → 45.5px. 이것이 manifest 의 `runStride`.**
  몸은 프레임마다 한 걸음의 1/4(68.75px)을 간다. 그래서 디딘 발의 **발끝**(발바닥 앞 끝)은 R1 → R2 → R3 에서 프레임마다 68.75px 씩 물러나야 한다(±3px, 발 미끄럼 기준).
  v2 에서 잰 발끝 x(엉덩이 기준): 가까운 발 98 → 30 → -37, 먼 발 103 → 35 → -34 (한 걸음 270 / 274px). 발목이 아니라 발끝을 재는 이유: R3 에서 발이 발끝으로
  굴러 발목은 그보다 덜 물러난다. 검사는 발끝 두 번의 물러남에서 한 걸음을 되잰다(= 2 x (R1 발끝 - R3 발끝)); 요청값에서 ±14px 를 넘으면 실패
- 엉덩이 높이(검사기가 재는 엉덩이 중심): 닿음 180px · 내려앉음 178px · 밀어냄 182px · 뜸 184px → **오르내림 5.5px(게임 0.9px)** — 거의 평평, 살짝 뜨는 느낌만.
  **허용: 24px 이하(넘으면 경고 — 깡충거림), 아래 한계 없음**(엉덩이가 아주 평평해도 된다: 치달림은 숙임이 만든다). v1 의 37.5px 는 이제 경고다.
  내려앉음(R2·R6)의 엉덩이는 그 반쪽에서 가장 낮다 — 받아내는 프레임(그 반쪽의 가장 낮은 엉덩이보다 2px 넘게 높으면 경고). **뜸에서 가장 높을 필요는 없다**(뜸에서 눌려도 된다 — 4판은 가눈 뒤 일어선다)
- 뜬 프레임의 바닥 틈(맨 아래 픽셀 ~ y=870): R4 23px, R8 24px(게임 4px; v1 41 / 37px). **18px(게임 3px) 미만이면 실패.** 디딘 프레임에서 반대 발은 바닥 위 56px 이상(12px 미만이면 실패)
- 상체: 앞으로 기울기(엉덩이→목 점) 닿음 24.0° → **내려앉음 19.3°(가장 일어섬)** → 밀어냄 29.1° → **뜸 31.2°(가장 숙임)**(수치표 0.30~0.51rad; 걷기는 8~11°).

## 8. 공격 뼈대 — 주인이 준 참고의 리듬
(프레임 단위 공격 마네킹 `atk__<시트>` 의 프레임·검사 수치는 10절이다. 아래 A1 준비 · A2 타격 · A3 지나침 · A4 수습은 그 시퀀스의 hold · contact · follow · recover 에 해당한다.)
- 프레임: A1 준비(지금의 wind-up) · A2 타격(지금의 strike) · A3 지나침(무기가 타격선을 25~40° 지나감, 엉덩이 +0.08머리 더 앞, 기울기 +0.10) · A4 수습(대기로 절반쯤 돌아옴).
  posekit 의 attack_3·attack_4 가 이미 이 자세를 갖고 있다
- 시간(0.5초 안): 준비 — 단검 100~120ms / 검·창 150~180 / 망치·양손 220~260 / 활 당기기 200~240 / 마법 모으기 240~300. 타격 60~100ms, 지나침 100~120, 수습 80~120.
  **준비가 타격 전 시간의 40% 이상** ("타격 순간보다 준비 자세를 오래 보여 주는 것이 리듬의 핵심")
- 움직임의 방향이 뒤집혀야 한다: 머리 x(두 발 중점 기준)의 부호가 A1 → A2 에서 바뀌고 100px 이상 이동, 엉덩이 55px 이상. 찌르기는 무기 끝 x 이동 165px 이상, 베기는 무기 각도 A1 → A3 120° 이상.
  활은 예외(꼿꼿이 선다): 준비 = 당기는 길이(시위 손 이동 100px 이상)
- 무기는 실루엣 밖: A1·A2 에서 무기 픽셀의 60% 이상이 마젠타 위, 무기 끝은 몸 둘레에서 33px 이상 밖. 무거운 머리(망치·철퇴)는 A1 에서 머리 위·뒤(얼굴 앞 금지)

## 9. 엔진과 맞물리는 것
- 걷기 프레임이 있는 시트는 `anims.walk` 를 걸은 거리로 넘긴다. 한 걸음의 게임 px 은 manifest `walkStride` (= `pose.json` 의 `walk_stride_game_px`, 143px 걸음이면 23.7).
  이 값이 그림의 실제 걸음과 다르면 발이 미끄러진다 — 등록할 때 반드시 적는다
- 걷기 프레임이 없는 시트는 엔진이 다리를 나눠 움직인다(`js/battle.js` `walkTf`). 그려 주는 프레임이 이보다 나아야 의미가 있다:
  지나가는 다리의 굽은 무릎, 두 다리의 교차(먼 다리 어둡게), 팔 엇갈림, 무기를 든 걷기 자세, 머리카락·망토·치마의 한 프레임 늦은 따라옴
- **달리기 프레임이 있는 시트**: `anims.run = {from, to, ms:[...]}` (기본 7칸 대기4·공격2·피격1 뒤에 이어 붙인 칸, 시트와 같은 칸 크기·앵커, 같은 `frames` 배열)과
  `runStride` = 한 걸음에 가는 게임 px (= `pose.json` 의 `run_stride_game_px`, `run_base` 는 45.5; n 프레임 = 두 걸음). 걷기의 `anims.walk` / `walkStride` 와 같은 모양이다.
  전투 이동(달리기·돌격·도주)은 `anims.run` 을 쓴다(주인 결정 2026-11-26). `anims.walk` 는 그 밖의 걷는 걸음(둔화·뒷걸음·달릴 빠르기가 안 되는 느린 자리 옮기기)에 쓴다.
  맞붙은 채 잔걸음에는 둘 다 쓰지 않는다
- 달리기 칸의 박자: 엔진은 그려진 달리기 칸을 **코드 달리기와 같은 박자**로 넘긴다 — 한 걸음 = min(`runStride` × 그리는 배율, 코드 달리기의 보폭) (`js/battle.js`).
  그래서 그려진 보폭(`run_base` 45.5px)이 실제 땅 위 이동(1배속 전사의 보폭 약 20px)보다 길어도 되고, **게임 크기에서 디딘 발이 조금 미끄러지는 것은 예상된 것이다**
  (칸마다 (`runStride` × 배율 − 보폭) / 4). 그려진 보폭이 더 짧으면 그 보폭대로 넘긴다(발이 붙고 걸음이 빨라진다)
- 달리기·걷기 띠는 **`tools/art/add_gait.py` 로 이미 등록된 시트에 붙인다** — 바닥 줄 y=870 → 칸의 anchor y, x=192 → anchor x 로 모든 프레임을 같은 자리에 맞춰
  뜬 프레임(R4·R8)도 제 높이를 지킨다. **`sheets.py` 로 변환하지 않는다** (`sheets.py` 는 자세마다 맨 아래 픽셀을 발 높이에 붙여 뜬 프레임이 바닥에 내려앉는다).
  명령은 `art/README.md` 「달리기·걷기 프레임 붙이기」
- 걷기 띠는 그 캐릭터의 기본 시트와 같은 배율(0.1654)로 변환한다. 64px 에 다시 맞추지 않는다. 대기(엉덩이 1.40머리) → 걷기(1.62~1.75머리) 전환에서 머리가 원본 24~38px(게임 4~6px) 올라가는 것은 정상

## 10. 공격·피격·대기 마네킹 시퀀스 (`atk__` · `hit__` · `idle__`, 2026-11-26)
프레임 단위 전투 시트(`docs/plans/2026-11-26_motion_frames.md`)의 마네킹. 값의 출처는 JSON 이다 — `tools/art/specs/motion_bible.json`(계통 × 동작의 프레임 이름·ms·contact·hold·cut,
`checks_by_kind`, 피격 `hit.weights.*.checks`)과 `tools/art/specs/motion_chars.json`(캐릭터의 계통, 피격 무게 `hit.sheets`, `timing.ms`, 마네킹 덮어쓰기, 축발 `mannequin.pivot_foot`).
이 절은 검사기가 그 값을 **어떻게 재는지**와 JSON 에 없는 판정 기준을 적는다. 이 절과 JSON 의 숫자가 다르면 JSON 이 이기고 이 절을 고친다.
**주인 결정(2026-11-26)**: 마네킹 시퀀스는 PC 가 클라우드의 사양으로 만든다(클라우드는 세트별 초안을 굽지 않는다 — PC 가 `walk8_pc.py` 처럼 스스로 짜거나 걷기·달리기 `.aseprite` 초안의 몸을 틀로 쓴다) ·
캐릭터마다 다르게 움직인다(캐릭터별 덮어쓰기, 두 캐릭터의 가이드 프레임이 같으면 안 된다) · 피격은 믿을 만한 움찔(무게별 K1·K2, 발은 바닥).

### 10.1 이름·납품·검사 명령 (모든 작업이 기대는 약속 — 바꾸지 않는다)
- 세트 id = `<동작>__<시트 stem 에서 sheet_ 를 뺀 것>`, 동작 = `atk` | `hit` | `idle`.
  예: `atk__class_warrior`, `atk__captain_shadowqueen`, `atk__captain_ironwall`, `atk__class_archer`, `hit__class_warrior`, `hit__captain_shadowqueen`, `idle__class_warrior`.
- 요청: `art/requests/guides/<set>/README.md` (+ 출발 파일이 있으면 같은 폴더). 납품: art-inbox `art/inbox/guides/<set>/<set>.aseprite` **하나만**.
  프레임 PNG·미리보기는 클라우드가 이 파일에서 뽑는다(`--export 폴더` → `f<NN>_<프레임 이름>.png`, NN = 설계표 순서로 0부터 두 자리, 이름의 빈칸·기호는 `_`;
  `<set>_preview.gif`, `pose_measured.json`). PC 는 PNG 를 올리지 않는다.
- `.aseprite`: 프레임 384x1024, **설계표의 프레임 하나 = Aseprite 프레임 하나**(순서 그대로, droppable 프레임도 마네킹은 만든다).
  프레임 시간 = 설계표 ms, 그 캐릭터의 `timing.ms` 덮어쓰기 반영(브리긴다 hold 170 · contact 80 · follow 80). 대기의 `idleTempo` 는 엔진이 재생할 때 곱하므로 파일에는 넣지 않는다.
  **태그**: 동작 이름의 태그 하나(`attack` / `hit` / `idle`)가 1번~마지막 프레임을 모두 덮는다. 프레임 이름 태그(`hold`, `contact`, `K1 impact` …)는 넣어도 되고, 넣으면 설계표의 그 프레임에만 있어야 한다.
  **레이어**(4절): Background · arm_far · leg_far · leg_near · torso · head · arm_near · joints(숨김) 필수, weapon_back · weapon_front · shield (cloth_back · cloth_front) 는 있으면.
  **무기와 방패는 자기 레이어에** — 검사기가 무기 끝·각도·방패 앞면을 그 레이어의 픽셀에서 잰다(쥔 손 = 그 레이어에 가장 가까운 손 점, 프레임들의 중앙값; 활은 레이어 픽셀의 중심에 가까운 손 점 — 10.4).
- 검사(PC 가 납품 전에, 클라우드가 받을 때 — 같은 명령):
  `python3 tools/art/check_skeleton.py <set>.aseprite --motion <attack|hit|idle> --set <set id>`
  (PC: `uv run --no-project --with pillow --with numpy python tools/art/check_skeleton.py ...`). 파일 이름이 `atk__` / `hit__` / `idle__` 로 시작하면 `--motion` 은 생략해도 된다.
  피격은 `--idle <그 캐릭터의 idle 세트>.aseprite` 를 더하면 그 1번(휴식) 프레임을 기준 대기로 잰다. `FAIL` 이 있으면 납품하지 않는다. `RESULT` 줄과 경고를 NOTES 에 옮긴다.

### 10.2 좌표 — 걷기·달리기와 다른 점
- 바닥 y=870 은 같다(3절). **엉덩이를 x=192 에 묶지 않는다**: 프레임은 세상 좌표이고, 디딘 발이 제자리에 있고 엉덩이가 움직인다(그 움직임이 준비와 맞는 순간을 읽히게 한다;
  등록할 때 클라우드가 엔진의 프레임별 몸 이동 `dx` 와 맞춘다). **대기 세트의 1번(휴식) 프레임만 엉덩이 중심 x=192 ±1** — 시트의 앵커 열이다.
- 공격의 몸 전체(모든 프레임을 같은 만큼)를 프레임 안에서 앞뒤로 옮겨 두어도 된다. 그림이 프레임 가장자리에 닿으면 실패(잘림), x=32~351 밖이면 경고(GPT 띠 칸의 마젠타 32px).
  안 들어가면 무기 드는 방식·발 너비를 바꾼다 — 배율은 하나다(3절). (시험: 뒷발 −1.0머리 + 앞으로 뻗은 검은 320px 안에 겨우 든다.)

### 10.3 세 동작 공통
**실패** — 프레임 수가 설계표와 다름 · 동작 태그가 없거나 전체를 덮지 않음 · 프레임 이름 태그가 다른 프레임에 있음 · 프레임 시간이 설계표(+ `timing.ms`)와 다름 · 384x1024 아님 ·
4절 밖의 레이어 이름, joints 밖의 숨긴 레이어, joints 가 보임 · 관절 점이 빠지거나 제 부위 위에 없음 · 뼈 길이 ±2px 밖(6절의 길이) · 반투명 가장자리 · 머리 레이어가 비었거나 몸통에 안 닿음 ·
y=870 아래의 픽셀 · **어느 프레임이든 두 발이 모두 y=870 에서 떨어짐**(공격·피격·대기는 땅을 떠나지 않는다) · 그림이 프레임 가장자리에 닿음 · 이웃 두 프레임이 픽셀까지 같음(대기는 경고).
**경고** — 레이어 순서 · 그림이 x=32~351 밖 · 이웃 프레임의 게임 크기 실루엣 차이 8% 미만(**hold 프레임이 낀 쌍은 제외, 대기는 이 규칙 없음** — 설계표 `neighbour_exempt`) ·
머리 기울기 8° 초과(6절 — 몸통 기울기를 뺀 목 위의 기울기, 둥근 머리는 각도로) · 머리가 목에서 밀림: **머리 레이어 중심과 목 점 사이의 거리**가 1번 프레임보다 4px 넘게 달라짐
(피격은 10px: HIT_KEYS 의 `head_off` 가 머리를 0.05머리까지 민다). 거리만 잰다 — 몸이 기울며 머리가 목 둘레로 도는 것은 밀림이 아니고 위의 기울기 규칙이 본다(걷기·달리기는 6절의 방식 그대로).

### 10.4 공격 (`--motion attack`)
- 프레임은 캐릭터 계통의 `archetypes.<계통>.attack.frames`, contact·hold·cut 은 그 번호. 검·방패: in 70 · hold 160 · swing 50 · **contact 70** · follow 90 · recover 90 · settle 70 /
  쌍검(니클라): 60 · 110 · 50 · **60** · 80 · 80 · 60 / 활: nock 80 · raise 80 · hold 200 · **release 60** · follow 110 · lower 100 · settle 70.
- **축발(실패)**: `mannequin.pivot_foot` 이 가리키는 발이 그 구간 내내 제자리 — 매 프레임 발의 닻 하나가 구간 첫 프레임의 자리에서 ±3px(`pivot_foot_tol_src_px`):
  **발끝**(그 다리 레이어의 y=866~870 — 바닥 줄과 그 위 4줄 — 에 있는 발바닥의 앞 끝 x), **뒤꿈치 쪽 끝**(같은 줄의 뒤 끝 x), 또는 **발목 점**(x 와 y 각각). 발바닥은 y=870.
  뒤꿈치를 드는 것은 된다 — 발끝으로 굴러 발목이 올라가고 앞으로 나와도 발끝 자리가 그대로면 통과(발목을 축으로 발을 돌리면 발끝이 끌려 들어가니 발끝을 제자리에 둔다). 발끝을 들고 뒤꿈치로 버티는 것도 된다. 미끄러지면 셋이 다 움직여 실패.
  전사·브리긴다 = 뒷발(near) 전 구간 · 니클라 = in·hold 는 뒷발, swing 부터 앞발(far) · 궁수 = 두 발 모두. 캐릭터 항목이 없으면 적어도 한 발이 전 구간 제자리. 나머지 발은 디뎌 나가도 된다(브리긴다 앞발 +0.15머리).
- **준비가 읽힘(근접 `melee_swing` · `melee_thrust`, 실패)** — 머리 = 머리 레이어의 중심, 두 발목 점의 가운데에서 잰 x: **hold 에서 음수(발 가운데보다 뒤), contact 에서 양수**, 그 이동 100px 이상.
  엉덩이 중심 x 의 이동 hold → contact 55px 이상.
- **맞는 순간 = contact 프레임 하나(실패)** — 다음 중 하나가 contact 프레임에서 성립해야 한다:
  ① 칼날 레이어(weapon_front / weapon_back)의 각도가 swing → contact → follow 에서 **한 방향으로 돌고** swing → contact 가 10° 이상 — 타격선을 지나는 프레임(베기).
     **칼날 각도** = 쥔 손 점 → 그 레이어의 **먼 절반의 중심**(손에서 가장 먼 픽셀까지 거리의 절반 이상 떨어진 픽셀들의 평균 위치; 0° = 앞, 90° = 위) — 넓은 머리(철퇴·도끼)의 가장 먼 픽셀이 프레임마다 튀어도 각도는 흔들리지 않는다.
     **방패 밀치기와 함께일 때**: ②의 방패가 contact 에서 성립하면, 칼날이 swing → contact → follow 에서 한 방향으로 **합 25° 이상** 돌 때만 베기로 친다. 그보다 작으면 들고 따라가는 무기(베기 규칙 없음 — 브리긴다의 철퇴).
  ② 무기 끝 x(무기 끝 = 쥔 손에서 가장 먼 픽셀, 찌르기) 또는 방패 앞면 x(방패 레이어의 가장 앞 픽셀, 방패 밀치기)가 **그 프레임에서 가장 멀다** — 다음으로 먼 프레임보다 2px 이상(둘이 비슷하면 맞는 순간이 둘이라 실패). 찌르기(`melee_thrust`)는 ②의 무기 끝만 인정.
- **무기(실패)**: 베기(①로 맞거나, 방패 밀치기가 아닌 근접) — 무기 각도 변화 hold → follow 120° 이상. 찌르기 — 무기 끝 x 이동 hold → contact 165px 이상.
  방패 밀치기(②의 방패로만 맞는 것, 브리긴다) — 방패 앞면 이동 hold → contact 55px 미만이면 경고.
- **지나침**: 베기 — follow 의 칼날이 contact 각도를 설계표 `weapon_past_line_deg` 만큼 지난다(그 계통 `attack.frames.*.joints` 의 값, 없으면 설계표에서 처음 나오는 값 — 지금은 `sword_shield` follow 의 **25~40°**).
  범위 밖이면 경고, **최댓값 + 10°(지금 50°) 넘게 지나면 실패** — contact 프레임이 아직 휘두름 중간이다(타격선을 한 프레임 늦게 지난다: 타격선 자세를 contact 에 두고 follow 는 거기서 25~40° 더). 베는 칼이 둘이면 각각 잰다.
  거꾸로 돌면 ①이 성립하지 않아 맞는 순간 실패. 밀치기·찌르기 — follow 의 엉덩이가 contact 보다 뒤면 경고(설계표: +0.08머리 앞).
- **실루엣(게임 크기)**: swing → contact 15% 미만 실패(맞는 순간이 새 모양으로 읽혀야 한다), contact → follow 35% 초과 경고.
- **무기는 실루엣 밖(베기, 경고)**: hold·contact 에서 무기 레이어 픽셀의 60% 이상이 몸 레이어(팔·다리·몸통·머리) 밖, 무기 끝이 몸에서 33px 이상(8절).
- **돌아옴**: follow 다음 프레임부터 1번 프레임(들어가기 전, 대기에 가장 가까운 자세)과의 관절 점 평균 거리가 프레임마다 줄어든다 — recover 에서 줄지 않으면 실패, 그 뒤(settle) 는 경고.
- **활(`bow`, 8절의 활 예외 — 머리 뒤집힘 규칙 없음, 꼿꼿이)**: 활 손 = **무기 레이어 픽셀의 중심에 더 가까운 손 점**(프레임들의 중앙값 — 당긴 시위가 시위 손에 닿아도 활대가 레이어의 대부분), 시위 손 = 다른 손.
  실패 — 당기는 길이(활 손 x − 시위 손 x)가 hold 에서 100px 미만 · 그 길이가 hold 보다 앞 프레임(nock·raise)에서 이미 같거나 더 김 · 시위 손이 hold → release 에서 60px 미만 뒤로 ·
  시위 손의 가장 큰 뒤로 움직임이 release 로 들어가는 칸이 아님(맞는 순간 = 놓기). 경고 — 활 손이 hold → release 에서 6px 넘게 움직임(활 팔은 버틴다) · hold·release 의 몸통 기울기 10° 초과.
- 총·시전·짐승(`gun` · `cast` · `creature`): 지금은 공통 검사·축발·돌아옴만 재고 "계통 규칙 아직 없음" 경고 한 줄을 낸다(이 계통의 마네킹을 처음 요청할 때 붙인다).
- **덮어쓰기와 이 절이 다를 때**: `motion_chars.json` `mannequin.overrides` 의 머리 단위 값은 posekit 기본에서 출발한 제안값이다(계획서 부록). 2026-11-26 시험에서 그대로 지으면
  전사 hold 의 머리가 발 가운데 앞 +2px·이동 76px, 브리긴다 hold +19px·이동 57px 로 준비 규칙이 실패하고, 전사의 칼끝이 프레임 밖으로 나갔다. PC 는 이 절을 지키고 바꾼 값을 NOTES 에 적는다
  (캐릭터 사이의 차이 — 엉덩이·기울기·손·무기 각도·방패·축발 — 는 남긴다).

### 10.5 피격 (`--motion hit`)
- 무게 = `motion_chars.json` `hit.sheets`(없으면 계통의 `hit_default`). 프레임: 무거움 K1 brace 80 · K2 hold 110 · K3 settle 80 / 보통 **K1 impact 70** · K2 peak 100 · K3 recover 80 · K4 settle 70 /
  가벼움 **K1 impact 60** · K2 stagger 110 · K3 recover 90 · K4 settle 80. contact = K1 (예측하지 못한 피격도 K1 부터 읽혀야 한다). 무거움의 K2 hold 는 8% 규칙에서 빠진다.
- **기준 대기**: 설계표 `hit.idle_reference`(엉덩이 (0, 1.40)머리, 기울기 0.08, 발 −1.10 / 1.00)를 posekit 마네킹으로 세운 것, 두 발은 이 세트의 K1 두 발목 자리(K1 은 대기의 발 그대로),
  엉덩이는 그 두 발목의 가운데보다 **0.05머리(5.5px) 앞**(설계표 대기의 값 — 발 너비에 비례해 줄이지 않는다: 좁게 선 니클라도 몸무게는 같은 자리). `--idle` 이면 그 휴식 프레임.
- **대기 열(경고, `--idle` 없이 잴 때)**: 그 기준 대기의 엉덩이 x 가 **192 ±3px** 밖이면 경고 — 자세 전체가 대기의 열에서 벗어났다(피격은 대기가 선 자리에서 시작한다: K1 의 두 발 = 대기의 두 발, 전체를 옮긴다).
- **모든 프레임(실패)**: 앞발(leg_far)·뒷발(leg_near)의 맨 아래 픽셀이 y=870(**앞발 들림 0**, 뒷발도 들지 않는다) · 두 발목 높이가 대기와 ±3px(발바닥 평평, 뒤꿈치·발끝 들지 않음) ·
  앞 발목 x 가 대기와 ±3px · 뒷 발목 x — 보통·무거움 ±3px, 가벼움 0 ~ −33px(0.3머리 휘청 미끄럼, ±3) · **앞무릎이 대기 높이보다 1px 넘게 올라가지 않음** · 몸통(엉덩이 → 목 점)이 뒤로 15° 넘게 기울지 않음.
- **K1·K2(관절 목표가 있는 프레임, 실패)** — posekit `HIT_KEYS` / `handoff.py` `HIT_RULES` 의 숫자: 엉덩이가 대기보다 **12~30px** 낮음 ·
  머리 중심이 맞은 쪽 반대로(−x) **무거움 12~35 / 보통 25~60 / 가벼움 40~90px**(게임 2~6 / 4~10 / 7~15px) · K2 가 K1 보다 깊다(엉덩이가 더 낮고 머리가 더 멀리, 1px 여유 — 아니면 순서가 바뀐 것).
- **돌아옴**: K2 다음 프레임부터 대기와의 몸 관절 평균 거리가 프레임마다 줄어든다(첫 칸에서 줄지 않으면 실패, 그 뒤 경고). 마지막 프레임의 몸 관절이 대기에서 12px 넘게 떨어져 있으면 경고.
- (요청 README 대로 세운 시험 마네킹, 이 기준 대기로: 보통(전사) K1 14 / 32px, K2 21 / 46px · 가벼움(니클라) K1 18 / 50px, K2 26 / 69px, 뒷발 −34px — 엉덩이 낮아짐 / 머리 밀림)

### 10.6 대기 (`--motion idle`)
- 프레임: rest 260 · inhale 220 · top 260 · exhale 220 (날짐승은 `idle.flyer`). 숨쉬기 고리라 8% 규칙이 없다.
- **실패**: rest 의 엉덩이 중심이 x=192 ±1 이 아님 · 어느 발이든 rest 에서 2px 넘게 움직이거나 y=870 에서 떨어짐 ·
  **고리가 닫히지 않음** — 마지막 → 첫 프레임의 관절 평균 이동이 고리 안의 가장 큰 걸음 +1px 또는 첫 걸음(rest → inhale)의 2배 +1px 을 넘거나,
  그 실루엣 변화가 고리 안 최대 +2% 또는 첫 걸음의 2배 +2% 를 넘음(exhale 은 inhale 을 거꾸로 밟아 rest 로 돌아간다).
- **경고**: 어느 관절이든 rest 에서 12px(게임 2px) 넘게 움직임(숨쉬기는 1~2 게임 px) · 어떤 관절도 움직이지 않음(숨쉬기 없음) · 이웃 두 프레임의 관절이 같음(복사 — 순서 확인) · 엉덩이가 옆으로 2px 넘게.

### 10.7 검사기가 재지 않는 것
- 두 캐릭터의 마네킹이 닮았는지(준비·맞는 순간 IoU 0.8) — `node tools/art/requests.js --motion` 이 덮어쓰기와, 클라우드가 뽑은 프레임 PNG 로 잰다.
- 무거운 머리 무기의 준비 위치(머리 위·뒤), 발사 원점 표시, 얼굴 표정, 그리고 첫 관문(게임 크기 재생에서 맞는 순간을 짚는 시험) — 사람·GPT 가 본다.
- 프레임 이름은 이름 태그가 있을 때만 직접 잰다. 태그가 없으면 순서가 바뀐 것은 자세 수치(준비·맞는 순간·K2 가 가장 깊음·돌아옴)로만 잡힌다 —
  대기의 inhale 과 top 을 서로 바꾼 것은 수치로 잡히지 않는다(같은 관절의 이웃이 생기면 경고만).
