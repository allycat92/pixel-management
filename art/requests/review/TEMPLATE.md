# 교차 검수(xcheck) 양식

Claude 의 판단을 GPT 가 다른 눈으로 다시 보는 절차. 대기열에 `review/xcheck_NN` (kind `review`) 으로 올린다. 그림은 그리지 않는다.

## 언제 반드시 하나 (ACCEPTED 전에)
1. 주인이 반려한 뒤의 다시 그리기 — [F] 문항 포함
2. 사람형이 아닌 몬스터·보스의 첫 납품
3. Claude 가 "메모(다시 그릴 필요 없음)"로 넘기려는 판독 의심 — [B] 문항으로
4. 새 연출·새 뼈대처럼 기준이 되는 것

## 문항 종류 (README 에 번호와 종류를 적는다)
- **[B] 가림(blind)**: 게임 크기 1배·4배 조각만 보여 준다. 파일 이름·글에 정답이 없어야 한다. "이 무기는 무엇인가? 다리는 몇 개로 세어지나? 눈이 먼저 가는 곳은?"
- **[F] 충실도(fidelity)**: 시안과 납품을 게임 크기로 나란히. "다음 중 살아남은 것은: <꼭 남길 것 목록>? 항목마다 예/아니오"
- **[C] 고르기**: 이름표 없는 A/B
- **[N] 수치**: 기준값이 타당한가
- Claude 의 판단은 맨 끝 절 「Claude 의 판단 (답한 뒤에 읽을 것)」에만 적는다 — 문항에 미리 드러내지 않는다 (xcheck 1·2 는 "측정은 모두 통과했다"고 먼저 적어 유도했다)

## 답 형식 (NOTES.md, 문항마다 한 줄)
`N. OK | FIX | UNSURE — 확신 높음/중간/낮음 — 누가: GPT 다시 그림 / PC 손질 / 코드 / 없음 — 바꿀 것: <px·색> — 이유: <한 줄>`
`WRONG QUESTION: …` 은 언제나 허용.

## 받은 뒤 (Claude)
OK 는 그대로. FIX 는 "누가"에 따라 대기열·코드에 반영하고 feedback.md 에 표로 남긴다. Claude 와 갈리면 주인 위임 범위(디자인 방향을 크게 바꾸지 않는 것)는 Claude 가 정하되,
지금까지 갈린 한 건(엘리노어 철퇴)은 GPT 쪽이 맞았다 — 판독 문제에서는 GPT 의 FIX 를 기본으로 따른다.
